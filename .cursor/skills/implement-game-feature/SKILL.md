# 实现游戏功能

## 前置条件

- 已有可观察的验收标准和明确非目标。
- 涉及的产品边界与 ADR 已确认。
- 工作区状态、Godot 版本和外接盘挂载正常。

缺少会改变行为的关键信息时返回设计流程，不自行发明产品规则。

## 流程

1. 阅读相关 Rules、设计文档、ADR、现有测试和 Git 状态。
2. 将工作拆为可独立验证的小步，先实现纯领域规则和测试。
3. 添加功能用例与接口，再接入存储、时间或平台适配。
4. 最后装配场景与 UI；不得让 UI 成为数值或存档真相源。
5. 每步运行最小相关验证，失败时定位根因后修复，不绕过门禁。
6. 检查存档兼容、离线结算、数据边界和失败恢复是否受影响。
7. 同步设计/架构/ADR，检查 diff、意外产物、素材登记和密钥。
8. 所有相关检查通过后按里程碑创建 Conventional Commit。

## 完成输出

- 实现的玩家行为与未实现范围。
- 关键文件和架构选择。
- 实际执行的命令及结果。
- 存档/更新/兼容性影响。
- 提交哈希和仍存在的风险。

禁止自动上传构建、发布版本、修改线上清单或处理真实签名材料。
