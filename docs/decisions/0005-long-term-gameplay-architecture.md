# ADR-0005：长线玩法总架构

- 状态：已接受。玩法层次继续有效。文中的单机离线边界由 ADR-0006 取代。突破确定成功已被 ADR-0007 取代。
- 日期：2026-09-11
- 决策者：项目负责人

## 背景

ADR-0003 打开了“修为挂机 + 历练挂机”的第二条循环，`0.1.15` 已把装备、功法、短板墙和五小时目录做成可玩闭环。ADR-0004 又把产品目标明确为 Android 竖屏、单机离线优先、3–6 个月。现在需要决定各系统如何互相供需、如何进入页面、何时解锁，以及怎样避免长线内容退化成更多互不相干的按钮。

本决策扩展 ADR-0003，不废弃其战斗、行囊、装备、功法、设置和统一时间入口。当前基线是应用 `0.1.15`、存档 schema 4；计划目标是 schema 5。

## 决策

### 一套核心、四个层次

长线玩法采用以下固定层次：

1. **修为轴**：时间、心法和丹药产生修为；突破消耗修为并提高境界。突破继续确定成功，不增加随机失败。
2. **历练轴**：玩家选择地点和构筑，战斗产生装备、功法残页及经营素材；短板墙、地点层和头目承接阶段挑战。
3. **洞府经营面**：灵田、丹房、器室、藏经阁把时间与素材转为定向产出。经营必须服务前两轴，不能生成一套与战斗、修炼无关的独立数值。
4. **传承元循环**：达到阶段终点后，玩家自愿建立传承快照，以部分进度重启换取有限的永久路线选择；传承改变下一轮构筑，不替代当轮内容。

关系固定为：

```text
修为轴 ──境界资格──> 历练轴
   ↑                    │
   │ 丹药/心法          │ 装备、残页、药材、矿材、见闻
   │                    ↓
   └──────── 洞府经营面 ────────┘
                    │
                    │ 阶段建设与图鉴成果
                    ↓
                传承元循环
                    │
                    └── 下一轮起点与路线差异
```

### 经营设施边界

- **灵田**：投入种子、时间与洞府灵气，稳定产出药材。解决丹药完全依赖随机掉落的问题。
- **丹房**：按已发现配方消耗药材，产出修炼或战斗的限时丹药；不直接产修为或永久属性。
- **器室**：消耗矿材、兽材和重复装备，定向合成槽位胚子、执行既有合阶或一次性温养；不做无限随机重铸。
- **藏经阁**：消耗残页与研修时间，定向补足已见功法的参悟进度或解锁构筑知识；不能凭空生成尚未见过的天阶功法。
- **洞府中枢**：决定离线容纳、并行队列和设施等级。升级增加选择容量，不直接按百分比碾压所有战斗数。

每个设施发布时必须同时具备投入来源、产出用途、队列决策、容量限制、取消规则、可见反馈和保底路径。只有图标、倒计时或“敬请期待”的设施不进入可见页面。

### 资源与经济原则

- 修为仍是修为轴专用资源，不承担建筑、装备和功法的通用货币职责。
- 灵石承担洞府升级与配方执行的通用费用，但不能单独替代关键素材。
- 药材来自灵田和历练，用于丹房；矿材与兽材来自历练，用于器室；残页来自历练，用于功法和藏经阁。
- 重复装备可合阶或拆成器材；已见功法残页可参悟、小成或投入研修。每类重复产出至少有两个有边界的去向。
- 主线必需物必须有确定性来源或累计保底；随机掉落只改变速度和构筑，不得造成永久死锁。
- 资源不使用真实时间过期，不设付费加速，不以广告换关键产出。

完整供需账本见 `docs/design/long-term-progression.md`。

### Android 竖屏信息架构

长期仍只保留五个底栏入口，不增加第六底栏：

- 修炼：境界、修为、渡劫与传承预览。
- 历练：地点、驻留战斗、头目、见闻与远行队列。
- 洞府：中枢和四项设施。
- 行囊：装备板、物品、材料、丹药和配方。
- 功法：运转、参悟、门派、传承配方与构筑预览。

`0.1.15` 当前的“设置”迁入全局顶栏齿轮，“洞府”成为第三个一级入口；设置、存档与版本更新保持随时可达。迁移只在对应系统达到完整发布标准时执行，禁止先放空洞府页。

### 统一时间与结算

- 所有系统只使用 `TimeService` 提供的一段可信经过时间。
- 一次启动只进行一次原子结算：读取快照、钳制时长、按段首状态计算各域结果、统一提交、保存新时间戳。
- 经营投入在队列开始时预留；同一离线区间内新产出的材料不能反向喂给本区间另一队列，避免结算顺序改变收益。
- 当前 8 小时离线上限属于 `0.1.15` 数值基线。长线阶段通过配置和洞府中枢逐步提高普通收益容纳，核心目标是允许至少一天间隔；所有域共享同一有效时长，不得各自重复领取整段时间。
- 时钟回拨按零处理并记录；本地单机只做完整性、幂等和异常提示，不假装能够彻底防作弊。

### 传承边界

- 传承只在完成明确章节、境界和洞府条件后开放，首次软飞升目标窗口为 Day 21–35；Day 90 进入多世构筑，Day 180 前形成第二种可验证终局路线。
- 传承必须由玩家主动确认，操作前保存独立恢复快照，并清楚列出保留项与重置项。
- 永久保留：图鉴与纪事、已完成里程碑、外观与设置、传承点、已选传承印记。
- 按轮重置：境界、修为、主线关卡层、普通装备与消耗品、当轮设施等级。具体清单进入确认页且由配置版本化。
- 传承点只解锁有限互斥或有上限的起始路线，例如偏修炼、偏历练、偏经营；禁止无上限全局乘区堆叠。
- 玩家可继续当前轮而不传承，不以弹窗、资源衰减或内容锁强迫重置。

### 分里程碑交付

- **里程碑 0（已完成）**：`0.1.15`、schema 4，五小时修为/历练双轴目录。
- **里程碑 1（Day 1–7 骨架）**：schema 5、阶段目标、供需账本、洞府中枢与灵田/丹房的完整最小闭环。
- **里程碑 2（Day 7–30 构筑）**：器室、藏经阁、定向保底、第二批地点与可回看的纪事。
- **里程碑 3（Day 30–90 收束）**：经营专精、章节终点、传承预览与首次可恢复传承。
- **里程碑 4（Day 90–180 复玩）**：互斥传承路线、第二轮差异化目标和终局后的持续沙盒。

每个里程碑都要深入完成其中系统，不以跨里程碑一次铺满页面代替闭环。详细解锁、验收和失败防线见 `docs/design/long-term-progression.md`。

## 备选方案

- 保持纯双轴，只继续加境界和关卡：未采用。缺少定向供给和阶段收束。
- 把经营做成独立模拟游戏：未采用。会出现与修炼、历练互不相干的第三套数值。
- 用随机重铸、无限词条和装备淘汰支撑时长：未采用。背包压力与不可控挫败会超过构筑收益。
- 用强制飞升清空进度：未采用。缺少可恢复性，也会惩罚不愿重开的玩家。
- 增加更多底栏：首页数量不能替代系统深度，也不适合 Android 竖屏单手操作。

## 后果

### 正面

- 每一类产出都有去向，修炼、战斗和经营形成可解释的供需网络。
- 当前五小时内容自然成为 Day 1 入口，已有投入和 ADR-0003 保持有效。
- 传承给数月进度提供阶段终点与新路线，同时保留单机玩家的自主节奏。

### 代价与风险

- 页面重组、schema 5、多队列离线结算和传承快照都需要独立迁移与恢复测试。
- 经营材料过多会造成认知负担；每个里程碑必须控制同时新增的资源家族。
- 若传承路线最终收敛成同一最优解，需要调整互斥效果，而不是继续叠加新货币。

## 验证与回滚

- 以 `docs/design/long-term-progression.md` 的 Day 1 / 7 / 30 / 90 / 180 检查点做压缩时间模拟和人工流程验收。
- 任一资源从零开始都能追溯到不依赖随机的基础来源；任一强制消耗都有至少一个玩家可控的获取路径。
- 离线结算、队列取消、满包、迁移、传承确认中断和恢复快照必须有测试。
- 页面迁移前后功能可达性等价；洞府未达发布标准时保持 `0.1.15` 五页。
- 若长线模块验证失败，隐藏对应内容入口并停止新队列；schema 5 字段保留，已产生资源不得静默删除。
