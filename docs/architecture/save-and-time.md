# 存档与离线时间设计

2026-10-02 起，多人进度以 [ADR-0006](../decisions/0006-online-product.md) 的服务器时间和已发布配置为准。本文描述的是当前 `0.6.3` 客户端的本地存档。接入账号前，这些规则继续保护这版客户端；接入后，手机本地只保留会话缓存。

## 目标

设备断电、写入中断、应用升级和内容更新不得轻易破坏玩家进度。离线收益必须可测试、可迁移且由一个时间入口计算。

当前事实基线是应用 `0.1.15`、存档 schema 4。ADR-0005 的长线玩法计划目标为 schema 5。schema 5 扩展多域队列与传承恢复，不改变原子写入、相邻迁移和统一 `TimeService` 原则。

## 存档信封

业务数据外层至少记录：

```json
{
  "schema_version": 4,
  "app_version": "0.1.15",
  "content_version": "0.1.15",
  "saved_at_unix": 0,
  "payload": {},
  "checksum": ""
}
```

`payload` 只保存不能可靠重算的玩家状态。

- schema 2：行囊、穿戴、已学功法、当前关卡、战报种子与设置。
- schema 3：装备合阶与温养、功法等阶、地点层、斩杀计数和丹药时效。
- schema 4：运转中的心法 id 与战技 id 列表。
- 计划 schema 5：阶段目标、经营资源与队列、确定性奖励/保底计数、见闻纪事、受保护溢出和传承状态。

缓存、界面滚动位置和可由配置推导的数据不进入存档。v1–v3 旧档顺序迁移到当前 schema 4；旧档合阶为 0、层为外围、功法按入门，运转栏按 `docs/design/five-hour-skills.md` 的温和补位规则初始化。

## 写入流程

1. 从领域状态生成快照，不直接序列化场景节点。
2. 校验字段、范围和引用的配置 ID。
3. 写入同目录临时文件并确保完整落盘。
4. 重新读取并校验临时文件。
5. 将当前有效存档轮换为备份，再原子替换正式文件。
6. 记录成功时间；失败时保留原有效存档。

启动加载依次尝试正式存档、备份和安全的新档流程。自动恢复必须记录原因并告知用户，不静默覆盖异常数据。

传承额外要求：

1. 预览只在内存计算，不改正式存档。
2. 玩家二次确认后，先写一份独立、只读的传承恢复快照。
3. 快照校验通过后再生成新轮状态并走正常原子写入。
4. 任一步失败都保留原轮；禁止出现一半保留、一半重置。
5. 恢复快照与日常滚动备份分开标识，后续自动保存不能立即覆盖。

## 迁移

- 每次格式变化递增 `schema_version`。
- 迁移函数只处理相邻版本：`v1 → v2 → v3 → v4 → v5`。
- 迁移前保留原文件；迁移后执行完整校验。
- 测试至少包含最老受支持版本、上一版本、当前版本、损坏文件和未知新版本。
- 无法理解更高版本存档时拒绝降级写回，避免永久损坏。

`v4 → v5` 的默认规则：

- 原有修为、境界、装备、行囊、功法等阶与运转栏、关卡层、斩杀、丹药、战报种子和设置原样保留。
- 阶段目标根据已完成的境界、地点和见闻做幂等回填；不能重复发首胜奖励。
- 新资源账本、设施等级、队列、保底和传承状态使用显式默认值。
- 尚未开放的设施不创建运行队列，也不提前投放无用途资源。
- 内容 ID 变化必须有版本化映射；找不到旧 ID 时进入安全占位并保留原始数据，不静默删除资产。

## TimeService

所有功能依赖抽象时间源，生产环境由系统时间实现，测试使用可控假时间。模块不得直接调用系统时钟。

当前修为与历练离线结算遵循：

1. 读取上次可信保存时间和当前时间。
2. 负时长按零处理并记录时钟回拨。
3. 对间隔应用已确认的离线收益上限。
4. 使用纯函数按区间计算收益，不逐秒模拟。
5. 一次性提交状态并保存，确保重复启动不会重复领取。

长线多域结算仍只消费同一段有效时长：

1. 读取结算前完整快照、`last_settled_unix` 和当前时间。
2. 计算非负经过时长，并按当前离线容纳钳制。`0.1.15` 当前上限为 8 小时；长线计划基础至少 24 小时，中枢可逐步提高到 36/48/72 小时。
3. 经营队列的投入在开始时已经预留。按段首队列状态判断完成，不允许使用本段新产出反向启动或喂给另一队列。
4. 修为、历练、经营分别从同一个段首快照计算结果；Day 30 远行不能与当前地点重复领取两份完整战斗收益。
5. 合并离线摘要，校验资源非负、引用有效、容量与保底单调。
6. 在内存中一次提交所有域，更新唯一 `last_settled_unix`，原子保存后才向界面宣告领取成功。

禁止每个系统维护自己的“上次领取时间”并各领完整离线段。允许队列保存 `started_at_unix` / `finishes_at_unix` 用于完成判断，但它们不能替代全局结算水位。

## 容量与受保护产出

- 普通战斗掉落按玩家的满包策略处理，并写入摘要。
- 唯一物品、首见物品、保底奖励和阶段目标奖励进入持久临时收纳箱，不因普通行囊满而丢失。
- 设施成品先进入设施产出缓存；玩家收取时再进入资源账本或行囊。
- 临时收纳箱与设施缓存不按真实时间过期。达到安全上限时暂停继续生成对应受保护物品并提示，不能覆盖旧物。
- 到达离线上限只截断新增普通收益；已投入队列、已有库存和已经完成的成品保持不变。

当前 `0.6.3` 客户端仍无法彻底防止改本地时间。ADR-0006 已经把多人进度的时间改为服务器时间。在接口接入前，不要在这版本地流程里假装已经完成服务器裁决。旧本地存档如何并入账号尚未决定。

## schema 5 队列不变量

- 队列保存设施 id、配方 id、开始/结束时间、已预留投入、确定结果或结果种子。
- 取消规则由配方声明；未开始全退，已开始按可见规则退还未消耗部分，唯一材料不得吞没。
- 同一队列重复结算得到同一结果；杀进程不能刷新随机结果。
- 保底计数只增不减，领取对应保底后按明确规则重置；内容更新不得静默清零。
- 资源账本永不为负，未知资源 id 不参与运算但保留原始值供恢复。
