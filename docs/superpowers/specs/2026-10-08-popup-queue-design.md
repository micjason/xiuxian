# 弹窗队列

- 日期：2026-10-08
- 状态：已确认
- 相关：ADR-0006、`docs/superpowers/specs/2026-10-08-player-login-design.md`

屏幕上同一时间只放一扇弹窗。系统通知进一条队列，按后台配置的优先级依次出现。玩家关掉当前这扇之后，才显示下一扇。

## 两类

**系统通知**由服务器决定要不要出现。这一版有三种：

| 类型 | 默认优先级 | 模板 | 按钮 |
| --- | --- | --- | --- |
| `version_update` | 1 | `confirm` | 下载更新、暂不更新 |
| `announcement` | 2 | `acknowledge` | 知道了 |
| `income` | 3 | `reward` | 收下 |

数字小的先显示。数字相同，按 `triggeredAt` 从早到晚。

**游戏内确认**由玩家点出来，例如物品详情。没有服务器优先级。系统通知正在显示时，这些点击不打开第二扇。游戏内确认正在显示时，新的系统通知进入队列，等这扇关掉。登录页不是弹窗，不进队列。

突破仍然是修炼页上的按钮，不另开一扇确认窗。

## 队列

游戏端只维护一个弹窗层。

- 收到通知时，按 `id` 去重。已经在显示或已经在队列里的同一 `id` 不重复加入。
- 当前没有弹窗时，取出队列头并显示。
- 当前有弹窗时，新通知只进队列，不盖住正在看的那扇。优先级更高的也要等这扇被关掉。
- 玩家关闭后，再取队列头。队列头是优先级数字最小的一条；数字相同则 `triggeredAt` 更早的一条；时间也相同则 `id` 字典序更小的一条。
- 某条通知从后续接口结果里消失，并且它还在队列里、还没显示，就从队列去掉。正在显示的那扇保留到玩家关闭。

关闭指玩家点了该模板上的按钮。点卡片外面不关闭。

## 卡片

三种模板共用一张居中卡片，不用多扇引擎窗口。

基准画布 1080 宽。卡片宽 720、高不超过 840，因此左右各留 180。正文在卡片内按字换行。内容超过卡片高度时，正文区域上下滚动，按钮留在卡片底部。标题、正文和按钮使用现有主题字号。

`confirm` 主按钮是「下载更新」，次按钮是「暂不更新」。`acknowledge` 只有「知道了」。`reward` 只有「收下」。

未知 `template` 的通知直接丢弃，不挡住后面的通知。

## 接口

`GET /me` 增加查询参数 `versionCode`。没传或传了非数字时按 0 处理，从而仍会收到版本更新。响应在原有修炼字段之外返回 `notices`。没有待显示的通知时，`notices` 是空数组。

```json
{
  "notices": [
    {
      "id": "release-23",
      "type": "version_update",
      "priority": 1,
      "template": "confirm",
      "triggeredAt": "2026-10-08T03:30:00.000Z",
      "payload": { "version": "0.6.7", "notes": "说明" }
    }
  ]
}
```

三种载荷：

- `version_update`：`version`、`notes`。
- `announcement`：`title`、`body`。
- `income`：`cultivationGained`、`countedSeconds`、`hitCap`、`offlineCapSeconds`。

`POST /me/notices/:id/dismiss` 记下这个玩家已经处理过该 `id`。之后的 `GET /me` 不再返回它。

按钮行为：

- 「暂不更新」「知道了」「收下」关闭卡片，并调用 dismiss。
- 「下载更新」沿用现有下载和安装流程，关闭卡片，不调用 dismiss。同一次登录内不再弹出同一 `id`。玩家下次打开时如果安装包版本仍低于该版本，通知重新出现。

dismiss 请求失败时，这张卡片仍然关闭，本次登录不再显示该 `id`。下次 `GET /me` 若仍返回它，再进队列。

## 生成规则

优先级和是否启用读弹窗类型表。类型被停用时，不返回该类型。

- 版本更新：当前已发布安装包的 `versionCode` 大于客户端传来的 `versionCode`，且该玩家未 dismiss 这个发布 id。`id` 为 `release-<versionCode>`。`triggeredAt` 用该发布记录的创建时间。
- 公告：启用中的公告，且该玩家未 dismiss。`id` 为公告 id。`triggeredAt` 用公告的启用时间。
- 收益：这一次结算计入的秒数达到 60，且获得修为大于 0，才生成一条。每 5 秒一次的常规刷新不产生收益弹窗。`id` 为 `income-<结算前的 lastSettledAt>`。`triggeredAt` 用这次结算的服务器时间。同一 `id` 被 dismiss 后不再返回。

收益正文由 `reward` 模板用载荷拼出：获得修为、结算时长、是否顶到离线上限。历练掉落和洞府产出不在这一版的载荷里。

## 后台

左侧在「版本更新」下面增加「公告」和「弹窗」。

**弹窗**只有三行，对应上面三种类型。可以改优先级和启用。优先级是不小于 1 的整数，允许重复。模板随类型固定，页面上只展示，不能改成另一种模板。不能新增第四种类型。

**公告**可以新增、修改和停用。字段是标题和正文。启用后，还没点过「知道了」的玩家会收到它。停用后，尚未显示的不再下发；已经开在屏幕上的，等玩家关掉。

版本说明仍在现有「版本更新」页填写，不在弹窗页改。

## 游戏端替换

登录成功后的系统弹窗只来自 `GET /me` 的 `notices`。本地的离线结算窗和版本窗不再自己 `popup`。修炼页上的离线一句摘要可以保留，它不是弹窗。

## 这一版不做

- 让高优先级打断正在看的弹窗。
- 在后台临时增加一种没有模板的新弹窗。
- 把历练掉落、洞府产出放进收益弹窗。
- 点卡片外面关闭。
