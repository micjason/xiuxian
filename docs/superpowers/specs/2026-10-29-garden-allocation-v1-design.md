# 药园分配 v1 设计（想不想修真风）

日期：2026-10-29  
状态：可玩版已按主路 A 实现（数值可再调）。成鹏看真机后再改文案。  
前置：洞府 v1（地块种收 / 炼丹 / 强化入口）已合入 `dev2`；本设计在其上叠加资源分配与设施升级  
范围：药园为主，炼丹吃同一套灵仆分配；强化仍复用炼器，不新建规则

## 目标

玩家在洞府里管理有限「灵仆」，决定药园与炼丹哪边收益更高；设施升级消耗材料。保留现有种地→收草药→炼丹闭环，分配是调收益的主操作，不是推倒重来。

## 资源（v1 先 3 种）

| 资源 | 作用 | 来源（v1） |
|------|------|------------|
| 灵石 | 已有货币；升级可选消耗 | 现有经济 |
| 灵木 | 设施升级主材料 | 关卡掉落（与种子同管线）+ 后台可配的少量初始/兑换 |
| 灵仆 | 可分配劳动力（整数） | 洞府/药园升级、关卡或任务赠送（后台表） |

不做：肉/人/木原名、第四种以上资源、自由多建筑产线。

## 灵仆分配

- 玩家拥有 `servantTotal`；已分配之和 ≤ 总数。
- v1 两个槽：`garden`（药园）、`alchemy`（炼丹）。未分配的闲置不产生收益。
- 改分配：客户端拖条/加减 → `POST` 服务器权威写入 `state.dongfu.allocation`，即时生效。
- 效果（后台可配，出厂默认建议）：
  - 药园：每名灵仆缩短成熟时间（如 −5%/人，下限 20% 原时长）或提高单次收获数量（二选一；**默认缩短时间**，更好感知）。
  - 炼丹：每名灵仆缩短队列中配方的剩余/标准炼制时间（同上百分比规则）。
- 分配变更不重置已在种/在炼的绝对到期时间算法：以「当前配置效率」重算剩余，或简单按写入时快照——**实现选重算剩余**，避免玩家无感。

## 设施升级

- 药园、炼丹各有 `level`（从 1 起）。
- 升级消耗：灵木为主，可选灵石（后台 `upgradeCosts[level]`）。
- 药园升级效果（默认）：`plotCount += 1`（比纯加速更直观）。
- 炼丹升级效果（默认）：`alchemyQueueLength += 1` 或炼制基础加速；**默认 +1 队列**（上限后台封顶，如 4）。
- 洞府总等级 v1 仍可不做；若展示，仅装饰。

## 与现有种地的关系

- 地块、种子、成熟领取、一键领取 **全部保留**。
- 种子仍走关卡掉落 + 物品；草药进背包炼丹。
- 灵仆不替代种子，只改效率。

## 状态与接口（草案）

`state.dongfu` 增补（示意）：

```text
allocation: { garden: number, alchemy: number }
servantTotal: number
gardenLevel: number
alchemyLevel: number
```

新/扩接口（均服务器权威）：

- `POST /dongfu/allocate` `{ garden, alchemy }`
- `POST /dongfu/upgrade` `{ facility: "garden" | "alchemy" }`
- 现有 plant / harvest / craft / claim 继续；结算时读等级与分配。

## 后台配置（必须跟上）

在现有「游戏配置 → 洞府」页扩展，不另起菜单：

1. **资源**：灵木物品 slug、灵仆获取表（可选简化为 globals 字段）。
2. **分配效果**：每仆对药园/炼丹的时间系数或产量系数、下限。
3. **升级表**：每级消耗（灵木/灵石）与效果（+地块 / +队列）。
4. 已有：地块默认、种子、配方、炼丹队列——保留。
5. 强化：继续用现有炼器/精粹配置页，洞府只入口。

校验：升级引用的物品 slug 必须存在；分配系数合法。

## 客户端

- 洞府总览或药园顶：灵仆总数、已分到药园/炼丹、闲置；快捷加减。
- 药园/炼丹页：当前等级、下一档消耗与效果、「升级」按钮。
- 红点：可升级（材料够）、可领取（已有）。

## 明确不做（本切片）

- 三维资源相克、多建筑自由建造、灵仆战斗、分配到强化、加速道具、爆炉。
- 推倒地块改纯速率条（若成鹏强要「完全想不想修真」，另开 B 案）。

## 验收

1. 能把灵仆分到药园/炼丹，成熟或炼制时间有可见变化。  
2. 能用灵木升级药园（地块 +1）或炼丹（队列 +1）。  
3. 原种收/炼丹/强化入口仍通。  
4. 后台能改分配系数与升级表并发布生效。

## 迭代

先按本方案出可玩版；成鹏看真机效果再改数值与文案。资源显示名可再换成更修仙的叫法，slug 稳定即可。
