# 产品边界与长线路线

当前事实基线是应用 `0.1.15`、存档 schema 4。下一阶段计划目标是 schema 5。ADR-0003 定义的五小时双轴已经落地；ADR-0004、ADR-0005 把产品目标扩展为 3–6 个月，但不把尚未实现的长线系统写成当前能力。

## 产品定位

- Android 优先的竖屏 2D 单机放置修仙游戏。
- 目标形态坚持单机离线优先；无网络时可完成所有核心成长、经营、战斗、传承和存档操作。
- 先验证成长反馈和 3–6 个月留存结构，不追求正式美术。
- 参考同类产品的交互密度，但不复制其名称、文本、数值、美术或代码。

## 可玩闭环

修为轴：

1. 玩家随时间获得修为。
2. 界面展示当前修为、获取速率和下一境界需求。
3. 修为满足条件后可尝试突破。
4. 突破成功进入下一境界，并提高修炼效率。
5. 退出并再次进入后，按统一规则结算离线收益。

战力轴（ADR-0003，与修为轴同时结算）：

1. 玩家选定已解锁关卡，挂机时按公式自动战斗。
2. 战斗记录与掉落进入行囊。
3. 按境界穿戴装备、学习功法，提高战斗数。
4. 战力与境界足够后可挑战下一关，掉落更高品质装备与更高阶技能书。

经营与传承（ADR-0005，分里程碑建设）：

1. 洞府经营把历练素材和经过时间转成丹药、定向装备与功法研修，反哺修为轴和战力轴。
2. 章节、见闻和建设成果在阶段终点形成可选传承。
3. 传承保留永久记录与有限路线选择，以局部重启改变下一轮路径；玩家可拒绝传承并继续当前轮。

完整页面、供需、解锁和失败防线见 `docs/design/long-term-progression.md`。

## 当前已具备（0.1.15 / schema 4）

- 可配置的境界、关卡、怪物、装备、功法与修炼/战斗数值。
- 可靠的本地存档、备份、v1→v2→v3→v4 迁移。
- 离线时间与一次结算（修为 + 历练）。
- 竖屏底栏：修炼、历练、行囊、功法、设置。
- Android 开发包的可重复构建。
- 为内容包和 APK 两层更新预留明确接口。

## 下一阶段必须具备（schema 5）

- 阶段目标、资源账本、确定性奖励与随机保底计数。
- 洞府中枢、灵田、丹房、器室、藏经阁；每个设施分里程碑发布，但发布时必须有完整投入、产出、选择和兜底。
- 多域共用一次 `TimeService` 离线结算，经营队列不能重复领取同一段时间。
- 持久临时收纳箱、设施产出缓存和传承恢复快照。
- Day 1 / 7 / 30 / 90 / 180 的压缩时间模拟与 schema 4→5 迁移验证。

## 明确不做

- 账号、云存档、PvP、排行榜、聊天、宗门多人玩法、跨服。
- 付费、广告、正式运营后台。
- 强制联网、服务器真挂机、论剑、无限随机重铸、多套一键装配、视觉战斗。
- 每日签到断档、真实时间过期的关键资源、限时绝版成长。
- 正式美术、批量剧情、配音和复杂动画。
- iOS 发布、应用商店接入和自动线上发布。

## 产品变更门槛

任何新增系统先说明其对双轴、经营供需、传承、存档格式、更新包、测试和工期的影响。新增系统必须按 `docs/design/long-term-progression.md` 的发布门槛做到闭环，禁止先放空页面。若改变离线单机、3–6 个月目标或明确不做项，必须由项目负责人确认并新增或更新 ADR。
