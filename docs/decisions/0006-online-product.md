# ADR-0006：可上架的多人版本

- 状态：已接受
- 日期：2026-10-02
- 决策者：项目负责人
- 取代：ADR-0004 中「单机离线优先、禁止账号、禁止服务器裁决、禁止强制联网」；ADR-0003 中「本阶段不做服务器和账号」。ADR-0005 的修为、历练、洞府、传承层次继续有效。

## 背景

已经上架更新渠道的客户端是应用 `0.6.3`（versionCode 20），本地存档 schema 5。它仍在手机上自行结算。项目负责人确认：这只是当前客户端，不是产品上限。目标是可上架、可给多人玩的完整游戏，包含游戏客户端、后台管理、后端接口和数据库。

## 决策

### 产品组成

- `game/`：Godot 4.7.2 竖屏客户端，负责展示和操作。
- `backend/`：玩家接口、结算、发布。技术为 TypeScript + Fastify。
- `admin/`：管理页面。技术为 Vue 3 + Element Plus。
- 数据库：与接口同一台机器上的 PostgreSQL。玩家进度、订单式存档和已发布配置以这里为准。

服务器尚未购买，`backend/` 与 `admin/` 尚未实现。文档不得把这两项目写成已完成。

### 权威数据

- 修为、境界、战力、突破、掉落由服务器按当前已发布配置计算，通过接口返回。
- 手机可以保留本次会话的展示缓存。缓存不是存档，断网不得被写成新的进度。
- 玩家进度保存境界、物品、技能的稳定编号。名称和每秒修为从已发布版本读取。
- 后台修改的是草稿。发布生成一份不可变版本，同时只有一份草稿和一份当前已发布版本。
- 结算使用服务器时间：用上次结算时间到本次请求的间隔计算，不按在线玩家每秒空转。

### 第一版接口

玩家注册和登录、打开游戏时结算、突破、返回战力，以及后台编辑境界、技能、物品并发布。洞府、门派、斗法、排行、聊天可以后续加，不在这一版里。

### 仍保留的边界

- 不复制竞品的代码、美术、文本、数值表和受保护名称。
- 不断签惩罚，不让关键成长到真实时间点作废，除非另有 ADR。
- APK 热更继续走现有 GitHub Releases 与 jsDelivr。业务接口和后台走独立服务器，不把游戏存档放进更新清单。
- 现有手机本地存档如何并入账号，尚未决定。未决定前不得静默丢档或静默覆盖。

## 后果

后续开发以本决策为产品边界。`docs/product/mvp-scope.md` 里与本决策冲突的「明确不做」不再执行。较大改动另写入 `docs/changes/`。
