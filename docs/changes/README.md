# 修改记录

较大改动写在这里，避免后面只剩聊天和零散提交。

## 什么时候写

写记录：产品范围、架构、存档或表结构、新服务、对外发布、规则或技能政策。

不写记录：文案、单点缺陷、不改变行为的整理。这些留在 Git 提交里。

## 怎么放

较大改动当天建立日期目录，一篇记录一个文件：

```text
docs/changes/YYYY-MM-DD/短横线英文名.md
```

同一天有多件较大改动时，共用这个日期目录，各自一篇。不要把当天的记录改写成对历史日期的覆盖。

## 一篇记录里写什么

- 决定了什么。
- 改了哪些规则、文档或代码。
- 哪些还没做，避免被写成已完成。
- 相关 ADR。

不写密钥、口令和聊天原文。
