## 0. 现状与结论（改造前发现的问题）

| 端 | 现状问题 | 本版处理 |
|---|---|---|
| 后台 | 近乎 Element Plus 默认样式；14 个菜单平铺；各页各写一份 `.toolbar`；Element Plus 控件文字是英文（OK / Cancel / No Data）；说明文字与正文无层级；布尔值显示 true/false；图表颜色写死在页面里 | 设计令牌 + 全局样式；菜单分 5 组；中文语言包；统一页头、说明条、标签；图表色走令牌；新增深色模式 |
| 游戏端 | 所有按钮都是同样的金色实心，没有主次；底部页签没有"当前页"状态；字号 16–28px 与 32–80px 并存，部分按钮字过小；没有适配刘海/手势条；密码框占位符与输入文字同色；登录错误提示用金色；境界印章底板渲染成黑方块；设置页字号过小 | 令牌 `UiTokens` + 主题 `MainTheme` + 导出 `.tres`；按钮分 主/次/幽灵/危险/页签/选项 六类；页签有选中态；最小字号 32px；安全区工具；印章底板清除 |
| 两端 | 无统一品牌色、无稀有度色、无战报色 | 两端共用同一色相体系：墨 · 青黛 · 金 · 朱砂；稀有度与战报色深色值两端一致 |

**风格结论：** "墨色为底，青黛为气，金为点睛，朱砂为警"。游戏端以深墨底 + 金线，适合夜间、竖屏、长时间挂机观看；后台以宣纸浅底 + 深墨侧栏，适合白天长时间填表。两端色相同源，所以看起来是"同一个项目"，但各自对比度与密度按使用场景单独调过。

## 1. 设计原则

1. **可读性第一，国风第二。** 国风只用在色彩、线条、印章、标题字体这些"不影响读数"的地方；数值、表格、战报正文一律用无衬线字体、高对比度。原因：这是一款数值驱动的放置游戏，玩家 90% 的时间在读数字和文字。
2. **一屏只有一个主操作。** 一屏最多一个金色实心按钮（游戏）/ 一个青黛实心按钮（后台）。原因：放置游戏的核心是"下一步该点哪"，主次不清会让新手迷失。
3. **信息分三层：** 标题（最大最亮）→ 数值与正文（主色）→ 说明（次要色，但仍满足对比度 4.5:1）。原因：你们的后台字段很多，需要靠层级而不是靠颜色数量来区分。
4. **不只靠颜色传达信息。** 稀有度同时有文字（"珍品"），战报伤害/治疗/暴击/增益/减益各有符号（− ＋ ★ ▲ ▼），状态标签带文字。原因：色觉障碍用户占比约 5–8%（男性），且手机在强光下颜色会失真。
5. **令牌化。** 业务代码不写颜色/字号字面量，只引用令牌（后台 `--xx-*`，游戏 `UiTokens`/主题变体）。原因：以后换风格、加深色模式、接入美术，只改一处。
6. **配置驱动的界面先把"为什么"写出来。** 后台每个字段都带中文名、单位、范围、默认值与一句话提示（见 §8.3）。原因：你们已决定"目标驱动"的数值编辑，运营看不懂字段就会配错。
7. **只改表现，不改逻辑。** 本版所有改动不触及接口、数据与业务流程。

## 3. 字体与字号

### 3.1 字体策略

- **不内置、不引用任何商用字体。** 使用系统字体回退链，所以没有字体授权风险。后台：苹方 / 微软雅黑 / 思源黑体（Noto Sans CJK SC）；标题可选宋体系（Songti / Noto Serif CJK SC），只用于登录页品牌字与页面大标题。
- 游戏端用 Godot `SystemFont` 回退链（`MainTheme`）。**未验证：** 在真实安卓机上 `Noto Serif CJK` 是否存在因机型而异；安卓上通常有 Noto Sans CJK，宋体系可能回退为黑体，这不影响可读性。
- **若要国风字体（如站酷、思源宋体）：** 思源宋体是 SIL OFL 可商用，需要内置字体子集（建议只含常用 3500 字 + 数字，约 2–4MB）。是否内置请客户决定（§11）。
- 数字用等宽或表格数字（后台 `.mono`），避免数值列跳动。

### 3.2 后台字号（px，桌面端）

| 令牌 | 值 | 用途 |
|---|---|---|
| `--xx-fs-xs` | 12 | 表单提示、辅助说明（下限） |
| `--xx-fs-sm` | 13 | 表格次要信息 |
| `--xx-fs-base` | 14 | 正文、表格、表单（行高 1.6） |
| `--xx-fs-md` | 16 | 区块标题 |
| `--xx-fs-lg` | 20 | 页面标题 |
| `--xx-fs-xl` | 28 | 登录标题、大数字 |

### 3.3 游戏端字号（1080×1920 画布像素）

**换算：** 以 411dp 宽的常见安卓手机为例，1 画布像素 ≈ 0.38dp（所以 40px ≈ 15dp，32px ≈ 12dp，128px 触控高度 ≈ 49dp）。仓库原有的大字号方向正确（Godot 画布会等比缩小），本版保留并整理成刻度。**最小字号 32px（≈12dp），不得再小。**

| 令牌 | px | 约合 dp | 用途 |
|---|---|---|---|
| `FS_HUGE` | 80 | 30 | 境界名 |
| `FS_VALUE` | 72 | 27 | 修为等核心数值 |
| `FS_DISPLAY` | 64 | 24 | 登录标题 |
| `FS_H1` | 56 | 21 | 页面标题 |
| `FS_HERO` | 52 | 20 | 大按钮 |
| `FS_H2` | 48 | 18 | 区块标题、关卡名 |
| `FS_BODY_L` | 44 | 17 | 重点正文 |
| `FS_BODY` | 40 | 15 | 正文、按钮 |
| `FS_CAPTION` | 36 | 14 | 说明 |
| `FS_MICRO` | 32 | 12 | 最小字号 |

为什么：安卓正文一般 14–16sp，所以正文 40px(≈15dp) 对齐；12sp 以下在手机上长时间阅读会累，故设 32px 下限；战报正文使用 `FS_CAPTION`（36px）。

## 4. 间距、栅格、圆角、阴影

- **间距基线：** 后台 4px（4/8/12/16/24/32/48），游戏 8px（8/16/24/32/48）。原因：后台表格密度大、需要更细粒度；游戏触控为主，用更大步长。
- **页面边距：** 后台内容区左右 24px，最大宽度 1280px（超宽屏居中）；游戏页面左右 24px（再叠加安全区）。卡片内边距：后台 16–24px，游戏 24px。
- **圆角：** 后台 4/8/12px；游戏 12/20/32px（卡片 20，按钮 20，大面板 32，药丸 999）。原因：国风偏方正，圆角不宜过大；游戏端圆角稍大是为了触控友好、视觉柔和。
- **阴影：** 后台卡片极轻（`--xx-shadow-card`），弹层较重（`--xx-shadow-pop`）；游戏端不用投影，用**边线 + 半透明表面**表达层级（Godot 投影成本高，且深底上阴影几乎不可见）。
- **边线：** 1px 细线，金色线仅用于选中与分隔强调（游戏）。
- **触控：** 最小触控高度 128px（≈49dp，高于 Android 推荐的 48dp），主操作按钮 144px，底部页签 160px，相邻可点控件间距 ≥ 16px。
- **安全区：** `UiSafeArea` 读取系统刘海/挖孔/手势条的安全区，返回画布像素并限制单边最大值；`play_screen.gd` 将它加到页面边距上。**未在真机验证**（桌面/虚拟屏幕返回 0）。

## 5. 图标规则

1. **图标不是必须的。** 没有美术阶段，所有功能必须在"只有文字"时可用；图标只做增强，不能是唯一标识（页签、按钮必须有汉字）。
2. 风格：单色线性，线宽 2px（后台 24px 栅格 / 游戏 64px 栅格），圆角端点；不使用多色拟物图标。原因：与"墨线"风格统一，且能用令牌换色。
3. 尺寸：后台 16/20/24px；游戏 ≥ 48px，触控图标 ≥ 96×96px 点击区。
4. 颜色：跟随文字色；选中为金（游戏）/ 青黛（后台）；不单独用语义色。
5. 符号替代：没有图标时用文字符号（战报用 − ＋ ★ ▲ ▼ ○ ◆）。这些符号在系统字体里都存在，不需要图标字体。
6. 现有 AI 生成图（页签图标、装备槽图标、洞府背景）保留，**上线前需确认商用授权**（已在先前决策里记录）。仓库里它们是 LFS 指针，本次未能渲染。

## 6. 组件规范

### 6.1 按钮

| 变体 | 游戏端（主题变体） | 后台（Element Plus） | 何时用 |
|---|---|---|---|
| 主 | `PrimaryButton`：金底 `#DBBD70` + 墨字，高 144 | `type="primary"`：青黛底白字 | 一屏一个：突破、挑战、保存、发布 |
| 次 | `SecondaryButton`：透明底 + 金边 + 象牙字 | 默认按钮：白底细线 | 返回、取消、次要动作 |
| 幽灵 | `GhostButton`：无边框 | `link`/`text` | 低频动作、"更多" |
| 危险 | `DangerButton`：朱砂边 + 朱砂字 | `type="danger"`（文字/链接形式用于表格行） | 分解、删除、回滚 |
| 页签 | `TabButton` / `TabButtonActive`：选中为金字 + 顶部金线 | `el-tabs` | 底部主导航 |
| 选项 | `ChoiceButton` / `ChoiceButtonSelected` | `el-radio-button` | 列表型选择 |

规则：禁用态用 `TEXT_DISABLED`（对比度 4.53）并保留边线，不能"消失"；按钮文字不超过 6 个汉字；破坏性操作必须二次确认（后台用 `ElMessageBox`，游戏用对话框）；**为什么**：改造前所有按钮同为金色实心，玩家无法区分"挑战"和"分解"，误触分解有真实损失。

### 6.2 输入框

- 游戏：高 128px，内嵌区底色 `#0C1413`，1px 边线，聚焦为金色边线；占位符使用次要色（改造前与输入文字同色，无法区分）。
- 后台：Element Plus 输入框，聚焦为青黛色 2px 焦点环（键盘可见，见 §9）；必填项标红 `*`；错误信息在输入框下方，朱砂色 + 文字。
- 规则：标签放在输入框**上方**（移动端更易读）；单位写在输入框右侧（后台 `suffix`）；不要只用占位符当标签。

### 6.3 卡片

- 游戏：`SURFACE` 半透明表面 + 细边线 + 20px 圆角；内嵌区 `InnerPanel` 再下沉一层；一张卡片只讲一件事。
- 后台：`.xx-card`：白底、1px 边线、8px 圆角、轻阴影；页面标题左侧有金色竖线作为国风点缀。
- 规则：卡片嵌套不超过 2 层。

### 6.4 表格（后台）

表头 `#F7F5EE` 底 + 次要文字色；行高 ≥ 44px；数字列右对齐并用等宽数字；ID/哈希用 `.mono`；操作列 `fixed="right"`（改造前境界页的操作列在 1440 宽下被挤出屏幕）；状态用标签（启用/停用），**不再显示 true/false**；空表显示中文"暂无数据"。宽表允许横向滚动，但操作列固定。

### 6.5 页签

游戏底部页签：修炼 / 历练 / 行囊 / 功法（现有 4 个），选中 = 金字 + 顶部 4px 金线 + 略亮底；后台没有页签，用侧栏。规则：页签最多 5 个；页签文字 2 个汉字，与图标同时出现时图标在上（图标可选）。

### 6.6 对话框与提示

- 对话框：游戏端 `AcceptDialog`/`ConfirmationDialog` 使用不透明面板 `SURFACE_SOLID` + 金色标题线 + 遮罩 `SCRIM`；主按钮在右。后台 `el-dialog`：标题 16px，正文内边距 16–24px，底部右对齐主按钮。
- 模态通知：游戏现有的 `NoticeLayer`（公告、离线收益、奖励）已改用令牌：遮罩 `SCRIM`、金色标题 52px、正文 44px、主/次按钮变体。后台 `ElMessage` / `ElMessageBox` 由全局样式统一。
- 轻提示（Toast）：游戏端**目前没有**轻提示组件（只有上述模态层）。规范约定：位置在页签上方居中，语义色边线 + 语义色文字（成功 / 警告 / 错误），停留 ≥ 2.5 秒，不遮挡主按钮；这是设计约定，本版未实现。
- 规则：错误提示必须说明"发生了什么 + 怎么办"，不使用技术错误码作为唯一文案。

### 6.7 列表项

游戏：高 ≥ 128px，左侧名称（稀有度色），右侧数值；行间距 16px；可点击项有按下态；装备项第二行显示"稀有度 · 部位 · 阶 · 强化等级"。后台：`el-table` 行或 `.xx-card` 列表。

### 6.8 进度条 / 经验条

高 36px，圆角药丸，轨道 `#0C1413`，填充青玉 `JADE_FILL`；**条上或条下必须有数字文字**（如"修为不足"、"236 / 360"），不允许只有条。到达上限（可突破）变金色。战斗中血条：我方青玉 → 低于 30% 变朱砂；Boss 血条用朱砂，条旁同样写数字。

### 6.9 稀有度徽标

圆角 4px（后台）/12px（游戏）、1px 同色边、浅色同色底（透明度 12%）、文字为档位名称。后台组件 `.xx-tag-rarity` + `rarity.ts`；游戏 `UiTokens.rarity_color()`。规则：名称文字不可省略；装备名称本身也用稀有度色。

### 6.10 文字战报

- 控件：`battle_report.gd`（`RichTextLabel` + BBCode），`add_round(n)` / `add_line(kind, text, amount)` / `add_result(won, text)`。
- 样式：每回合一个"—— 第 N 回合 ——"金色标题；每行 = 符号 + 数值（着色，带正负号）+ 正文（主文字色）；暴击的前缀（★ 暴击 −数值）加粗；状态用 `【】` 括住名称；名称中的 `[` 会转义，避免 BBCode 注入。
- 版式：正文字号 36px（`FS_CAPTION`，战报行数多，取比正文小一档），行距 +10px；一回合内按"行动顺序"排列；胜负结果行单独一行，胜利成功色、失败危险色；战报末尾显示"获得：…"战利品（稀有度色）与"再战一次 / 返回"两个按钮。
- 长战报：控件可滚动并**自动跟随最新一行**（已实现，`scroll_following`）。设计建议（未实现，待产品确认）：提供"跳到开头"，超过 50 回合时折叠中间回合。
- 为什么：文字战报是首发的"战斗表现"，没有美术，所以靠颜色 + 符号 + 层级制造节奏感；这也是玩家感受"数值成长"的主要窗口。
- **当前状态：** v0.2 已接入"历练"页的战报页签：用服务端 `battle.log`（`{t, side, damage, targetHpAfter}`）整理成回合文字战报；协议里没有暴击/技能/名称，回合是近似归并，字段定稿后再细化（§11）。

## 7. 游戏端页面布局（1080×1920 竖屏）与组件库（v0.2 重做）

### 7.1 通用骨架

顶部资源栏（112px：左"修仙"字标 + 演示标记（仅 mock 模式）；右"修为 / 战力"两枚药丸）→ 内容区（单张卡片，可滚动，左右 24px + 安全区）→ 底部页签（160px + 手势条安全区，5 个：**修炼 / 历练 / 角色 / 行囊 / 功法**）。弹层统一用 `GamePopup`。所有可点控件 ≥ 128px 高（1080 宽画布上约 49dp），相邻可点控件间距 ≥ 16px，最小字号 32px。

### 7.5 装备栏是数据驱动的，以及服务端缺口（重要）

部位只在 `SlotConfig` 里配置一次，界面从它生成，增减部位不改界面代码。**v0.3：服务端已有 6 个部位**（weapon / helmet / clothes / gloves / shoes / accessory），"手部"可穿戴；法宝、灵宠仍是 `locked:true` 占位（第三期）。

### 7.6 与服务端能力的差距（界面已画，功能需后端）

| 界面功能 | 现状 | 处理 |
|---|---|---|
| 出售 / 批量出售 | 服务端只有"分解"（得修为），没有出售和货币 | 界面不假装有出售，按钮就叫"分解（换修为）"，调用真实的分解接口；真正的出售等产品定了货币再做 |
| 强化 | 无接口 | 按钮显示但禁用，标"未开放" |
| 锁定 | 无接口 | 仅保存在本机（`user://item_flags.json`），换设备不同步；锁定的物品不能被批量选中 |
| 批量操作 | 无批量接口 | 客户端逐件调用单件分解 |
| 容量 | `/content/current` 的 `globals.bagCapacity` | 有则用，没有则默认 100；服务端是否真的限制容量需确认 |
| 战报明细 | `battle.log` 事件 `{t, side, damage, targetHpAfter}` | 用它整理回合；缺少暴击/技能/名称等字段，回合是按时间归并的近似 |

### 7.7 美术就位后怎么换

1. 物品图标：把 PNG 放到 `res://assets/art/items/<slug>.png`，`ItemSlot` 自动显示，文字占位消失。
2. 格子/弹层/按钮边框：在主题里覆盖 `ItemSlot`、`EquipSlot`、`GamePopup` 的 StyleBox，或改 `KitStyle`。
3. 颜色/字号：只改 `ui_tokens.gd`，导出 `.tres`，GUT 会校验同步。
4. 不需要改页面脚本和布局。

规则：
- 一屏一个主按钮；数值变化用颜色 + 符号（▲ ▼），不单靠颜色；空状态写原因和下一步；弹层必须有明确的关闭/取消。
- 登录失败、网络错误提示用朱砂色并且必须能看见——原仓库 `StatusLabel` 放在默认隐藏的 `UpdateCard` 内（原有问题，本版未改动逻辑，见 §11）。
- 旧场景节点（DollBoard、InspectPanel、BagTabs 等）仍在 `main.tscn` 中但隐藏，因为既有测试 `test_main_scene.gd` 依赖节点名；新页面通过挂载点接管。清理旧节点需要同步改测试。

## 8. 后台页面布局

### 8.1 布局外壳与信息架构（v0.2 重做）

- 左：220px 深墨侧栏，品牌"修仙后台"；菜单分 6 组（可折叠）：**概览**（运营概览）/ **玩家运营**（玩家管理）/ **游戏配置**（境界、物品装备、技能、关卡与 Boss、战斗公式与参数、洞府建筑）/ **发布中心**（草稿与发布、版本快照与回滚、客户端安装包）/ **运营活动**（公告、弹窗、邮件、礼包、兑换码、商品与订单）/ **系统**（管理员、操作日志、设置）。选中项：金字 + 淡金底 + 左侧金线；演示数据页菜单项带小圆点。
- 上：面包屑（分组 / 页面 / 当前记录）、**全局搜索（Ctrl+K）**、**草稿状态按钮**（未发布改动数 / 配置错误数，点击进入发布）、用户菜单。
- 内容区：宣纸底；每页统一"页头（标题 + 说明 + 右侧操作）→ 筛选条 → 列表/表单"。
- 菜单树只有一个来源 `admin/src/nav.ts`，路由、面包屑、搜索共用；旧地址有重定向。完整新旧对照见 `admin_ia_redesign.md`。

### 8.2 统一页面套路：列表 → 抽屉

列表页：顶部筛选（搜索 + 下拉）、右上"新建"（主按钮）、表格右侧**固定操作列**、批量选择与批量删除、分页；点编辑从右侧抽屉滑出（不离开列表），底部固定"取消 / 保存"（Ctrl+S），字段即时校验，不合法禁用保存并说明原因；抽屉有改动时关闭会提示放弃；删除为危险确认，清空玩家/回滚需输入对象名或版本号；加载/空/错误三态统一；支持 `?open=` 深链接。

### 8.3 配置表单与"字段说明卡"（schema 驱动，已落地）

每个配置页的**全部字段**都由 `admin/src/schema/resources.ts` 一份定义生成：表单控件、校验、表格列、说明卡共用。聚焦字段时右侧说明卡显示五项：**中文名、单位、范围、默认值、一句话提示**；英文键名放小字便于开发对照；超范围时输入框变朱砂色并写明范围，不允许保存。后端返回但 schema 没登记的字段，会列在"未登记字段"里，避免参数被悄悄隐藏。

### 8.4 发布中心（已落地）

三步：**① 配置体检（前端规则，错误阻止发布）→ ② 改动清单（新增只读 `GET /admin/draft/diff`，旧值→新值）→ ③ 发布（必填版本说明）**。顶栏常驻草稿状态。版本页：版本列表、任意两版对比、回滚（diff 预览 + 输入版本号确认）。

**注意：** 后端**没有回滚接口**（`POST /admin/draft/rollback` 不存在）。页面遇 404 会提示"后端尚未提供"。截图里的成功流程来自本地 mock 服务，仅作演示。

### 8.5 目标驱动编辑器（未来页面，静态样板）

按你们"目标驱动"的方向：运营不直接改一堆系数，而是设定"目标"，由工具推算系数并给出可视化。

- **成长时间线：** 横轴是游戏时长（小时/天），纵轴是战力/境界；里程碑（突破、Boss）用标记点；拖动目标点会提示"需要把修炼效率调到 X"。
- **难度条：** 每个关卡一根条——玩家推荐战力 vs 关卡战力，用"轻松 / 合适 / 吃力 / 劝退"四段色带（颜色 + 文字标注）。

图表色使用色盲友好的蓝/橙，并用实线/虚线区分，不单靠颜色（令牌 `--xx-chart-*`）。

### 8.6 审计日志（已落地：系统 / 操作日志）

时间（等宽）/ 操作人 / 动作（中文标签）/ 对象 / 摘要 / 结果（着色）；按时间、操作人、动作筛选。"点击行展开变更前后对比"仍是设计，需要后端保存变更前后的值（目前操作记录只有摘要）。

### 8.7 运营活动页（演示数据）

邮件、礼包、兑换码、商品与订单后端都没有对应模块。页面用统一的 `MockCrudView`（浏览器本地存储）演示交互，页头有"演示数据"标记，菜单有圆点。目的是让客户确认字段与流程，**不是已上线功能**。

## 9. 无障碍与可用性

1. 对比度见 §2.6，主题单元测试守护游戏端。
2. 颜色冗余：稀有度有名称，战报有符号，状态标签有文字，图表有线型。

### 9.1 游戏端美术系统

- 所有美术从 `ArtLib`（`game/scripts/ui/art/art_lib.gd`）取：框体、图标、背景、字体。换成正式美术 = 同名文件覆盖，九宫格边距在 `ArtLib.NINE` 表里，业务代码不动。
- 框体：`assets/art/ui/*.png`，96px 贴图，九宫格边距约 30–36px，按钮、面板、品质框、进度条、红点、分割线、底栏。由 `tools/assets/build_ui_frames.py` 程序生成（原创，无授权问题）。
- 图标：`assets/art/icons/*.png`，白色剪影，运行时按品质或状态染色；`assets/art/items/<物品编号>.png` 若存在则优先使用（全彩正式图标的挂载点）。
- 背景：`assets/art/bg/*.webp`，公开领域的中国古画裁切调色（首页、登录、行囊、角色、功法、六个关卡主题）。

- 来源、作者、授权：`game/assets/ASSETS_LICENSES.md`；游戏内「设置 → 致谢与版本」读取 `assets/credits.json`。CC BY 3.0 的图标必须保留署名。

### 9.2 页面结构

底部五页签（修炼 / 历练 / 角色 / 行囊 / 功法），各带红点：可突破、有更强可穿装备或可强化、行囊有新物品、有功法书。顶部栏显示境界、战力、修为、强化经验。

- 修炼：灵气环 + 大主按钮「突破」，挂机收益，下一步建议。
- 历练：关卡卡片（古画背景 + 首领头像），首领详情与掉落，战报。
- 角色：英雄卡 + 装备栏（6 核心部位 + 法宝、灵宠预留），点部位看详情或换装。
- 行囊：容量条（初始 20 格）+ 强化经验、分类页签、网格、批量分解。没有锁定，没有出售。
- 物品详情：属性、与已穿对比、强化卡（当前经验 / 下一级所需、「强化」「一键强化」；卡在突破节点时改为材料清单（现有 / 需要）和「突破」按钮，没到节点时显示下一个节点的要求）、「分解 +N 强化经验」（已穿戴的装备置灰，旁边写明「不能分解：已穿戴的装备不能分解，请先脱下」）。
- 功法：运转与停止。

### 9.3 后台

- 菜单：概览 / 玩家运营 / 游戏配置（新增「装备强化」）/ 发布中心（「版本历史」只读对比）/ 公告弹窗 / 系统。侧栏底部是灰色的「后续阶段」提示，不可点击。
- 删除：回滚、封禁、补发、邮件、礼包、兑换码、商品与订单。
- 「装备强化」页：通用规则 + 按品质设置（6 个品质，含红）+ 突破节点表（每个品质一个页签：节点等级、材料×数量、可批量补齐）+ 实时效果预览（曲线里标出需要突破的等级）；没有规则时只提示，不自动填默认值，需要点「填入建议起始值」再保存。强化经验池没有上限，页面里也没有这一项。
