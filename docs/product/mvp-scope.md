# MVP 产品边界

## 产品定位

- Android 优先的竖屏 2D 单机放置修仙游戏。
- 先验证成长反馈和留存循环，不追求内容数量与正式美术。
- 参考同类产品的交互密度，但不复制其名称、文本、数值、美术或代码。

## 首个可玩闭环

1. 玩家随时间获得修为。
2. 界面展示当前修为、获取速率和下一境界需求。
3. 修为满足条件后可尝试突破。
4. 突破成功进入下一境界，并提高修炼效率。
5. 退出并再次进入后，按统一规则结算离线收益。

## 首期必须具备

- 可配置的境界与修炼数值。
- 可靠的本地存档、备份和版本迁移入口。
- 离线时间与收益结算。
- 占位界面和基础反馈。
- Android 开发包的可重复构建。
- 为内容包和 APK 两层更新预留明确接口，不在首个闭环内实现。

## 首期明确不做

- 账号、云存档、排行榜、聊天、宗门多人玩法。
- 付费、广告、正式运营后台。
- 战斗、装备、洞府经营等第二核心循环。
- 正式美术、批量剧情、配音和复杂动画。
- iOS 发布、应用商店接入和自动线上发布。

## 产品变更门槛

任何新增系统先说明其对核心闭环、存档格式、更新包、测试和工期的影响。若改变以上边界，必须由项目负责人确认并新增或更新 ADR。
