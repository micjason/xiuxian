## 2. 炼器精粹 `refine_essence`（可堆叠材料，橙底，图标 `items/refine_essence`）
- 规则存放在 `content_globals.enhance.essence`，后台「装备强化」页的「炼器精粹 · 分解产出与强化消耗」里可以改：
  - 分解得到 = `slotOverrides[品质][部位]` ?? `round(yields[品质] × slotMultBp[部位] / 10000)`，再加上 `强化等级 × refundPerLevel`
  - 默认值：白 20 / 绿 60 / 蓝 150 / 紫 400 / 橙 1000，每级返还 40。部位倍数默认 100%，默认没有单独指定。
- 「配置概览 → 强化与分解」里显示品质产出、每级返还、基础消耗和增长倍数。

## 3. 强化改为消耗精粹
- 每升一级的消耗 = `costTable[品质][等级]` ?? `max(1, round(costBase × costGrowth^等级 × 品质倍数))`。默认 costBase 40、costGrowth 1.25，没有单独指定的等级。
- 突破节点的材料不变。精粹不够时服务器返回 `409 ESSENCE_SHORT {need, have}`，提示「炼器精粹不足，分解装备可获得」。
- 客户端装备详情（稿 q_enhance_cost）：
  - 新增消耗行「消耗 炼器精粹 · 拥有 / 需要」，够显示绿色、不够显示红色；强化经验进度条去掉了。
  - 精粹不够时按钮变灰，但仍可点，点了给出上面那句提示。
  - 「分解」按钮的副标改为「+N 炼器精粹」。
- 背包「材料」页会显示炼器精粹。

## 4. 强化经验一次性换算成精粹（迁移 0050 + `essence-migration.ts`）
- 换算公式：`精粹 = ceil(旧强化经验 × migrationRatioBp / 10000)`。换算时写一行 `enhance_exp_migrations`（player_id 是主键），把 enhanceExp 清 0。
- **每人只换一次**：在玩家结算时按需进行。后台也有「现在全部换完」按钮，以及进度统计（已换人数、换出的精粹总量、还没换的人数）。
- **默认比例 7000（0.7）为什么不会让任何人变弱：**
  - 对每个品质、每个等级 L，算出 r(L) = 新精粹消耗 / 旧经验消耗。默认曲线是旧曲线的 2/3（40 vs 60，增长倍数相同），四舍五入后最大的 r 约为 0.6718，所以 `minSafeMigrationRatioBp = 6718`。
  - 比例 ≥ 最大 r 时，任意一级的新消耗都 ≤ 比例 × 旧消耗。所以旧经验池能买得起的任何一段升级，换算后的精粹也一定买得起，战力不会下降。
  - 测试里对每个品质、每个起始等级、每一段升级都暴力验证过（`salvage-essence.test.ts`）。
  - 后台把比例调到低于安全值时会显示警告。
- 部分消耗对照（精粹 / 旧经验）：
  - 白：40/60、50/75、63/94、78/117、98/146
  - 蓝：50/75、63/94、78/117 … 373/559
  - 橙：64/96 … 1455/2183
- 注意：已经强化过的装备，分解返还从「已投入经验的 80%」改成了「每级 40」，高等级装备的返还会变少（不影响战力）。

## 5. 背包满
- `grantEquipment` 对来源 `stage_drop / boss_first / boss_repeat`（`tuning.bagFullSkipSources`，后台可配）：如果放不下，就不发，返回 `{skipped:'bag_full', bagFull:true}`。这一步在占用 requestId 之前，所以不会留下发放记录。
- `admin_grant / mail / event` 仍可以超出容量。离线、挂机结算走的是同一条路。
- **行为变化**：首领首通掉的**装备**，以前满包也会发（超容量），现在满包时不发；首通的非装备奖励照常发。
- 客户端（§17.5）：
  - 历练页挂机场景左上角显示「行囊已满」提示条（hint_bagfull_bg + 背包图标 + badge_full + 「去分解」脉冲按钮），点一下直接打开分解弹窗。远处的小怪往下挪 70。
  - 底栏「背包」的红点换成 `badge_full`。
  - 不再弹 `BagFullPrompt`。首领战结算里的「行囊已满，装备未拾取」，以及开发二号的挂机首领提示里的「（行囊已满，装备未拾取）」都保留，这样同一件事不会提示两遍。
