# ADR-0002：Android 两层更新

- 状态：已接受
- 日期：2026-09-09
- 决策者：项目负责人

## 背景

项目暂不计划上架应用商店，希望测试用户从游戏内获得后续版本，同时避免每次内容调整都重新安装完整 APK。

## 决策

- 配置、文本、图片和音频等通过签名 manifest 与 PCK 内容包更新。
- 引擎、原生插件、权限和不适合内容包承载的程序变更通过完整 APK 更新。
- APK 下载并校验后调用 Android 系统安装器，必须由用户确认覆盖安装。
- 发布始终保持同一应用 ID 和签名身份。
- 早期使用 HTTPS 对象存储/CDN，不采购常驻业务服务器。
- 构建自动化默认不上传、不发布、不切换线上 manifest。

## 备选方案

- 每次只发完整 APK：实现简单，但频繁更新流量和安装摩擦较大。
- APK 差分重建：复杂度、设备兼容和签名风险超出 MVP 需要。
- 任意逻辑热更新：增加安全、兼容和审核风险，不作为默认能力。

## 后果

客户端需要启动期内容加载、版本兼容、完整性校验和回滚能力；Android 需要自定义 Gradle 插件、FileProvider 与 `REQUEST_INSTALL_PACKAGES`。用户需允许当前应用安装未知来源 APK。

## 验证与回滚

实现阶段必须测试内容下载中断、哈希失败、空间不足、激活后启动失败、同签名 APK 覆盖安装和旧存档升级。内容失败回滚上一版本；APK 默认通过更高版本修复，不依赖降级。
