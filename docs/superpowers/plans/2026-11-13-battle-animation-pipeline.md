# 战斗动画生产流水线

**目标：** 后台上传视频，抽出帧并指定槽位，保存后游戏端立刻用这套序列帧播战斗动画。素材预览不依赖战斗；入战预览跟战斗时间对齐。后台用网页播放，游戏用 Godot，两边读同一份清单。

**已定：**

- 开发阶段不做草稿。保存即覆盖当前这一份，游戏下次读取就是它。
- 动画配置和战斗配置分开。伤害、出手、胜负仍由现有战斗时间轴决定。
- 两级预览：素材预览只播动作；入战预览套上战斗的命中时间。
- 自动完成抽帧和对齐。哪个帧属于哪个动作，由人指定。
- 一条视频一个动作。同一角色所有动作共用一个格子、一个缩放、一个锚点。
- 第一版不做法线抠图、不自动识别动作、不把行走和跳跃接进对打。

**技术：** Vue 3 + Element Plus 后台，Fastify 接口，ffmpeg 抽帧，sharp 处理图片，PostgreSQL 存清单，磁盘存 PNG，Godot `AnimatedSprite2D` 播放。

---

## 1. 要做的东西

分四段。前一段能单独验收，再做下一段。

### 1. 动画包和清单

一个角色一份当前包。清单是一份 JSON，网页和 Godot 都只认它。

清单里有：格子宽高、脚底点、朝向、每个槽位的帧文件、每帧时长、是否循环。槽位先定这些：

| 槽位 | 第一期 | 循环 |
|---|---|---|
| 待机 idle | 要做，进战斗 | 是 |
| 普攻 attack | 要做，进战斗 | 否，播完回待机 |
| 施法 cast | 要做，进战斗 | 否 |
| 出手 skill | 要做，进战斗 | 否 |
| 受击 hit | 要做，进战斗 | 否 |
| 倒地 down | 要做，进战斗 | 否，停在最后一帧 |
| 胜利 victory | 要做，进战斗 | 否，停在最后一帧 |
| 剑气 projectile、命中 impact | 单独的特效包，进战斗 | 否 |
| 行走 walk、跳跃 jump | 可以保存和素材预览 | 行走循环，跳跃不循环 |

战斗里还没有的槽位只保存，不播放。

保存后写数据库里的当前行，并替换磁盘上的 PNG。不保留「未发布」那一份。

### 2. 素材预览

后台页面用 Canvas 按清单播。不读关卡、不读伤害。

能做的事：选槽位播放、逐帧、洋葱皮、1 倍和 2 倍、棋盘格看透明、深色底看溢色。用来判断换脸、多手、脚滑、抠图破洞。

### 3. 视频拆帧和挑选

上传短视频。服务器用 ffmpeg 按目标帧率抽出 PNG，做成缩略图。

页面上框选帧，指定槽位，可删可排序。确认后 sharp 做三件事：按约定底色抠图并减溢色、用该角色已定下的同一套裁切和缩放放进格子、写出正式 PNG 并更新清单。

已经是透明 PNG 的帧不再抠一次。

### 4. 入战预览和游戏端

入战预览用一份固定样例战报：普攻、技能、受击、胜利。技能剑气必须在战斗配置给出的命中时刻到达。动画变长变短，不改掉血时间。

游戏端在打开历练或迷雾战斗前拉取当前包。清单的更新时间变了就重新下载。指定了动画包的角色，用包里的帧播。Godot 按同一份清单计算「第 t 秒是哪一帧、脚在哪」。

包已经指定但文件缺失或下载失败：战斗页直接提示不能播，不偷偷换回熊王静图或旧的 `battle_runtime` 帧。还没指定包的角色，继续用现在的播法。

## 2. 怎么做

### 数据

- 表 `animation_packs`：编号、名称、给谁用（主角，或某个首领 `artKey`）、清单 JSON、`updated_at`。
- 文件目录 `data/animation-packs/<编号>/<槽位>/00.png`。数据库不存图片字节。
- 主角同时只有一条当前包。首领按 `artKey` 各一条。保存就是更新这一条。

播放计算写进清单说明，两边照这个实现：

- 帧号 = 经过时间 ÷ 每帧时长，不超过最后一帧。
- 不循环的动作停在最后一帧，再由调用方切回待机。
- 脚底点是格子里的固定像素，不按每张图重新找脚。
- 普攻、出手可以带一个「向前像素」的直线位移，写在清单里。现有代码里的弹簧惯性先不放进第一期。

跳跃以后若要播，沿用抽帧时的画面高度，不把脚按回地面。

### 接口

都在现有 Fastify 上，沿用已经接好的 multipart。

- `POST /admin/animation-packs`：新建或覆盖当前包的清单。
- `POST /admin/animation-packs/:id/extract`：上传视频，返回临时帧。
- `POST /admin/animation-packs/:id/frames`：提交人选的帧和槽位，处理后写入正式目录并更新清单。
- `GET /animation-packs/current`：游戏端读取。按 `updated_at` 决定要不要重下文件。

抽帧放在独立处理里，不和玩家战斗请求挤在同一次计算。临时帧确认或放弃后删除。

ffmpeg 装在跑接口的机器上。图片用 sharp。底色默认品红 `#FF00FF`。容差先在一张样图上试，再批量用。

### 后台页面

游戏配置下增加「战斗动画」。

1. 包：主角一份，每个首领 `artKey` 一份。
2. 抽帧：上传、胶片、指定槽位。
3. 素材预览：Canvas。
4. 入战预览：同一 Canvas，喂样例战报和当前战斗的技能命中延迟。

战斗公式页继续管伤害和出手，不在动画页改这些数。

### 游戏端

`TimelineBattlePage` 已经通过 `CombatAnimationSlots` 播槽位。指定了包之后，`slot_actor.gd` / `fighter_actor.gd` 改为读下载下来的清单和 PNG，不再写死 `res://anim_q/battle_runtime/frames/`。

命中延迟仍用现在的 `skill_impact_delay()`。剑气飞行的终点时刻等于这个延迟。

下载目录用 Godot 的 `user://` 缓存。缓存键是包编号加 `updated_at`。

### 验收

- 同一清单、同一时刻，网页和 Godot 的帧号、脚底位置一致。用一组固定时刻做对时。
- 保存后不点发布，游戏重进战斗就能看到新帧。
- 缺帧、下载失败时战斗页出现明确错误。
- 素材预览不请求战斗结算。入战预览不改气血和胜负。

## 3. 为什么这样，好处是什么

视频模型出的是片，不是游戏帧。同行能用的流程都是：锁镜头、纯色底、一条视频一个动作、按游戏帧率抽帧、人来删帧、整段共用一个格子。逐帧各自裁切会让人在格子里晃，跳跃会被按回地面。

动画和战斗分成两套，是因为改一张受击图不应该改掉血。格斗游戏也把「第几帧打中」放在战斗数据里，画面只负责像。入战预览专门检查剑到的时刻和掉血时刻是不是同一个。

网页和 Godot 各写播放器，是因为后台不必嵌一套 Godot。前提是清单把帧号和脚的位置算死，并用固定时刻对时。这样后台看到的和手机上的帧是对齐的。震屏、着色器不在网页里复刻。

保存即生效，是开发阶段的约定。少一套草稿表和发布按钮，做坏了直接再保存一次盖掉。多版本留到正式上线再做。

这样做完之后，新角色是「定一张立绘、每个动作一条视频、后台挑选、两边预览、保存进战斗」，不用改 Godot 场景，也不用发新安装包。

## 4. 需要确认

下面每项给了建议。不确认之前不开始写代码。

1. **第一期做完的范围。** 建议做到第 4 段：主角这套包能在真实历练和迷雾里播。只做后台预览的话，看不出和战斗时间是否对齐。
2. **第一套角色。** 建议只做主角。熊王等首领沿用现在的静图，等主角这条链路验收后再用同一页面做首领。
3. **格子。** 建议新角色不要沿用现在约 130 像素高的旧表。格子用 640×320，脚底 `(240, 280)`，和现有合同一致，源视频人物高度至少约 560 像素，避免放大发糊。
4. **抽帧帧率。** 建议待机、行走 12 帧/秒，攻击、施法、受击 12 帧/秒。单段视频不超过 8 秒、50MB。
5. **背景色。** 建议品红 `#FF00FF`。衣服偏青白，绿幕会抠坏衣边。
6. **文件放哪。** 建议放在接口机器的本地目录 `data/animation-packs/`。现在是单机部署，先不上对象存储。
7. **行走和跳跃。** 建议第一期能上传、能在素材预览里看，战斗里不播。
8. **怪物飞弹。** 建议第一期只做主角剑气和命中爆炸。首领技能仍只用身体帧。
9. **直线前探。** 建议普攻向前 24 像素、出手向前 18 像素，写进清单。现有弹簧先不加，避免网页和 Godot 各算各的。
10. **没指定包时。** 建议保持今天的播法。一旦某个角色指定了包，缺文件就报错，不退回旧帧。

---

## 5. 先不做

- 草稿、发布、版本对比、回滚。
- 自动判断某一帧是走路还是受伤。
- 实景或渐变背景的 AI 抠图。
- 把行走、奔跑、冲刺、跳跃接进当前对打。
- 在动画页修改伤害、出手间隔、胜负。
- 用网页重写一套和清单无关的时间。
- 把 PNG 放进 PostgreSQL。
