# ADR-0003：打开历练第二条循环

- 状态：已通过
- 日期：2026-09-10
- 决策者：项目负责人
- 扩展关系：由 ADR-0004、ADR-0005 扩展。其中「不做服务器和账号」由 ADR-0006 取代。双轴本身未废弃。

## 背景

`0.1.5` 只有「时间产修为 → 突破」一条循环，前三阶约 90 秒，到筑基后期表就断了。负责人确认改产品边界：要完整的战斗、背包、装备、功法、设置，并且串成一条可重复的流程，而不是五张空页或最小演示。该历史背景描述的是当时基线；当前事实基线已是 `0.1.15`、存档 schema 4。

对照见 `docs/research/idle-xiuxian-systems-2026-09-10.md`。结构取自公开页，不抄名称、文案、数值、美术。

## 决策

自本决策起，单机本地允许第二条循环：**选关挂机战斗 → 掉落进有限行囊 → 按境界穿戴 → 学习功法 → 战力过墙 → 挑战下一关**。修为挂机与历练挂机共用同一个 `TimeService` 入口和离线上限，一次结算。

本决策覆盖完整流程，不是占位 Demo：

- 关卡按境界阶梯投放，每关多种怪物、掉落表、战力墙。
- 装备五槽（武器、头盔、衣服、鞋子、玉佩），五品质（白、蓝、紫、金、红）。
- 功法四阶（黄、玄、地、天），以技能书学习，学后改同一组战斗数。
- 行囊有限、可锁、可弃、满包策略可设。
- 设置独立页：战报、满包策略、音量、存档导出；更新入口移到此页。
- 界面为竖屏底栏：修炼 / 历练 / 行囊 / 功法 / 设置。

本阶段当时明确不做：服务器真挂机、账号、宗门多人玩法、论剑、付费、炼器重铸、多套装配、视觉战斗。账号和服务器已由 ADR-0006 纳入产品。无限随机重铸仍然不做。

本决策落地时存档 `schema_version` 升到 2，必须能从 v1 只含修为的旧档迁过来。此后五小时装备与功法方案已顺序迁移到 schema 4；ADR-0005 的长线阶段计划迁移到 schema 5。

## 与后续决策的关系

- ADR-0004 把“五小时可玩”扩展为 3–6 个月的单机留存目标，不否定本决策的修为/历练双轴。
- ADR-0005 在双轴外围增加经营供给与传承元循环；本决策定义的战斗、行囊、装备、功法和统一时间结算仍是长线架构的核心组成。
- `docs/design/five-hour-loop.md` 与 `docs/design/five-hour-skills.md` 是本决策在 `0.1.14`–`0.1.15` 的已落地深化；`docs/design/long-term-progression.md` 负责后续里程碑。

## 备选方案

- 方案 A：只做最小切片（1 关、3 怪、1 槽）。未采用：负责人要求完整流程并串联。
- 方案 B：服务器常驻挂机。未采用：超出单机边界，且 `mvp-scope` 仍禁止账号服务器。

## 后果

### 正面

- 回来有战报和掉落，突破之外有「花」和墙，内容不再几分钟点完。
- 修为轴与战力轴互相锁，符合已调研的放置结构。

### 代价与风险

- 存档变大，校验和迁移变复杂。
- 离线战斗用区间公式，不是逐回合重放；战报是摘要加抽样行。
- 内容表会反复改数字，规则必须读表，测试不能写死今天的攻击力。

## 验证与回滚

- v1 旧档能加载，修为与境界不变，历练从第一关空行囊开始。
- 在线/离线同一套战斗公式，重复启动不重复发掉落。
- 若历练破坏修为闭环或坏档无法恢复，回滚本决策对应代码，存档保留 v1 备份。
