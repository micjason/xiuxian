# ADR-0001：客户端技术基线

- 状态：已接受
- 日期：2026-09-09
- 决策者：项目负责人

## 背景

项目由 AI 主导实现，目标是先快速验证 Android 竖屏 2D 放置修仙核心循环，同时保持数值逻辑可测试和长期可维护。

## 决策

- 固定使用 Godot 4.7.2 stable 和强类型 GDScript。
- Android 为首发平台，首期使用占位美术。
- 客户端采用表现层、功能用例、纯领域规则和基础设施适配的单向依赖。
- 使用与 Godot 4.7.x 兼容的 GUT 9.7.x 作为首个测试插件。
- 一个主 Agent 负责端到端功能；仅在独立只读研究或审查时并行专用 Agent。

## 备选方案

- C#：工具链、移动导出和 AI 上下文成本更高，当前收益不足。
- 无测试插件：无法为领域数值和存档迁移提供可重复自动验证。
- 多常驻 Agent：早期模块边界尚未稳定，协调成本与冲突风险高。

## 后果

核心业务必须与 Node 解耦，场景主要承担装配和表现。Godot、GUT 与插件版本需要锁定，升级必须独立验证。

## 验证与回滚

首个垂直切片应证明领域逻辑可无头测试、场景可正常装配。若 GUT 9.7.x 与 4.7.2 实测不兼容，记录新 ADR 后更换测试框架或固定补丁版本。
