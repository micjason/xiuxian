# 后台管理系统 信息架构重设计（v2）

> 适用范围：`micjason/xiuxian` 分支 `dev`（本地改动，未推送）的 `admin/`（Vue 3 + Element Plus）。
> 起因：客户反馈"现在的设计不符合一个成熟、高级、好用的后台"，并明确**不必保留原有设计与分类**。本版因此不是换皮，而是重做菜单、页面套路和发布流程。
> 阅读提示：每个页面标注数据来源——**真实接口**（后端已有）、**新增只读接口**（本版在后端新增，只读、不改业务逻辑）、**演示数据**（后端没有对应功能，页面带"演示数据"标记，数据存在浏览器本地）。没有隐藏任何一种。

## 1. 改造前的问题（对照原代码 838d557）

1. 14 个菜单平铺，顺序按"开发顺序"而不是"运营顺序"：规则、境界、关卡、人偶、装备、物品、技能、洞府、发布、版本更新、公告、弹窗、用户、操作记录。
2. 同一件事被拆到多页：装备/物品是两页，技能/技能分类混在一页，掉落要跳到单独表单，"人偶"其实是战斗数值模拟工具却排在配置里。
3. 发布页只有一个按钮：不告诉你改了什么，也没有发布前检查；没有历史版本入口；没有回滚。
4. 每页自己实现列表、弹窗、校验，操作位置不一致；字段只有英文键或简短标签，运营看不懂单位和范围。
5. 没有概览页：登录后直接掉进某个配置表，看不到"有没有未发布的改动""配置是否有问题"。
6. 没有全局搜索、面包屑；危险操作（清空玩家）只有一个确认框；关闭抽屉/切换页面会静默丢失未保存内容。
7. 运营能力缺口（邮件、礼包、兑换码、商品订单）没有位置，后面加会破坏菜单。

## 4. 操作流程的改进

### 4.1 统一的"列表 → 抽屉"页面套路
- **列表**：顶部筛选（搜索框 + 下拉）、右上主按钮"新建"、表格右侧**固定操作列**、批量选择与批量删除、分页、列显示一致。
- **抽屉**：点"编辑/新建"从右侧滑出，不离开列表；底部固定"取消 / 保存"（Ctrl+S 保存）；字段**即时校验**（范围、必填、取整），不合法时保存按钮禁用并在字段下写明原因。
- **字段说明卡**（schema 驱动）：聚焦字段时右侧卡片显示 中文名 / 单位 / 范围 / 默认值 / 一句话提示；英文键名放小字。字段定义只写一份（`admin/src/schema/resources.ts`），表单、校验、说明卡、表格列共用。
- **未保存守卫**：抽屉有改动时点关闭/切换页面，会提示"放弃修改？"。
- **危险确认**：删除用危险色确认框；清空玩家、回滚这类高风险操作需要**输入对象名/版本号**才能确认。
- **状态**：加载、空（写原因与下一步）、错误（可重试）三态统一组件。
- **深链接**：`?open=<id>` 直接打开某条记录的抽屉，概览和全局搜索据此跳转。

### 4.2 发布中心：从一个按钮变成可控流程
1. **体检**：前端在发布前自查（境界顺序、关卡缺首领、掉率范围、关键参数缺失等），错误项阻止发布，警告项提示。
2. **改动清单**：调用新增的 `GET /admin/draft/diff?from=current&to=draft`，按资源分组展示新增/修改/删除，修改显示 旧值 → 新值（`ChangeList` 组件）。
3. **发布**：必填版本说明；成功后显示新版本号并提示去看版本列表。
- 顶栏常驻"草稿状态"按钮：显示未发布改动数和配置错误数，任何页面都能一键去发布。

### 4.3 版本与回滚
- 版本列表（新增只读接口 `GET /admin/draft/versions`），可选择任意两版对比。
- 回滚对话框：展示"回滚会改变什么"（diff）+ 输入版本号确认。**后端目前没有回滚接口**，页面调用 `POST /admin/draft/rollback` 遇 404 时提示"后端尚未提供回滚，请联系开发"，不会假装成功。演示用 mock 服务实现了该接口，所以截图里能看到成功流程——这只是演示。

### 4.4 其他
- **全局搜索**（Ctrl+K）：搜页面、境界、物品、技能、关卡，回车直达并打开对应抽屉。
- **面包屑**：分组 / 页面 / 当前记录。
- **概览页**：把"该做什么"放到首页——未发布改动、配置体检问题、境界分布、最近操作。
- **玩家管理**：详情抽屉里把"战力来源"（境界/装备/功法分项）和"最近操作"放在一起，运营排查"为什么这个玩家这么强"不必翻日志。
- **单一角色**：保持"只有管理员一种角色"的决定，不做权限矩阵；但操作日志保留，所有写操作都可追溯。

## 5. 后端接口清单（真实 / 新增 / 演示 / 缺失）

| 接口 | 状态 | 用在 |
|---|---|---|
| `/admin/auth/login`、`/healthz` | 真实 | 登录、概览 |
| `/admin/draft/{realms,items,skills,skill-categories,stages,puppets}`（GET/POST/PUT/DELETE） | 真实 | 各配置页 |
| `/admin/draft/gear`、`/gear-qualities` | 真实 | 物品装备 |
| `/admin/draft/rules`、`/formula-preview`、`/trial`、`/puppets/duels` | 真实 | 战斗公式与参数、试炼模拟 |
| `/admin/draft/drop-tables` | 真实 | 关卡与 Boss（掉落） |
| `/admin/draft/publish`（POST） | 真实 | 草稿与发布 |
| `/admin/players`、`/admin/players/:username/reset` | 真实 | 玩家管理 |
| `/admin/operations` | 真实 | 操作日志、概览最近操作 |
| `/admin/announcements`、`/admin/popup-types`、`/admin/releases`、`/admin/content/buildings` | 真实 | 对应页面 |
| `GET /admin/draft/versions` | **本版新增（只读）** | 版本列表 |
| `GET /admin/draft/diff?from=&to=` | **本版新增（只读）** | 改动清单、版本对比、回滚预览 |
| `POST /admin/draft/rollback` | **后端缺失**，前端已按 404 处理 | 回滚 |
| `GET /admin/draft/weapons` | 缺失（原页面调用的接口不存在）；前端改为从 `/admin/draft/gear` 取 | 物品装备 |
| 玩家封禁/解封、补发物品、玩家详情聚合 | 缺失 | 玩家管理（按钮禁用并标注） |
| 邮件、礼包、兑换码、商品订单 | 缺失（后端无对应模块） | 演示数据页 |
| 管理员账号管理 | 缺失（单角色决定下可延后） | 管理员页只读说明 |
| 概览统计（总玩家数、在线数等） | 缺失；现用 `/admin/players` 前端聚合 | 概览 |

新增的两个后端接口是**纯读**：`backend/src/modules/content/snapshot-diff.ts` 是纯函数（带 3 个 vitest 单测），`versions.ts` 读取已发布快照；没有改任何现有业务逻辑，也没有迁移。**未针对真实 Postgres 跑过**（本环境无数据库，后端的数据库类测试无法运行），请在有库的环境验证。

## 7. 已知限制

- 演示数据页（邮件/礼包/兑换码/商品）不会影响真实游戏，刷新浏览器也不会同步到服务端。
- 玩家详情的"战力来源"使用 `/admin/players` 已返回的 breakdown 字段（后端既有数据），前端只负责展示；"最近操作"按用户名过滤 `/admin/operations`。
- 仅按桌面 ≥ 1280px 设计与验证，窄屏未做。
- 概览的统计由前端从列表接口聚合，玩家很多时应改为后端统计接口。
- 后台的草稿读取：`loadCurrentWorld` 读取的是草稿而不是已发布版本（后端既有行为，本版未改，发布前请留意）。
