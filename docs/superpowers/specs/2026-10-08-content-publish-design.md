# 制作后台的内容发布

- 日期：2026-10-08
- 状态：已确认
- 相关：ADR-0006、`.cursor/rules/content-admin.mdc`

制作后台发布的是游戏内容。运营事务不在这里做。境界、关卡、物品、技能和掉落在同一份草稿里编辑，点一次发布，整份一起生效。

## 草稿里有什么

- **境界。** 名称、每秒修为、攻击、防御、气血、攻击间隔、突破所需修为、下一境界。突破只扣修为。
- **关卡。** 一关一个 Boss。Boss 有名称、攻击、防御、气血、攻击间隔。
- **物品。** 装备、技能书、丹药、材料。继续使用现有的名称、描述、种类、品质、部位和攻防气血速度。技能书必须选定一个技能。
- **技能。** 描述、角色（心法、武技、身法）、攻击、防御、气血、速度、修炼加成。用不到的数填 0。学习条件是所需境界，加上必须先学会的技能。
- **掉落。** 一条关系连接一个 Boss 和一件物品，带概率和数量。概率是 0 到 100 的整数，数量是不小于 1 的整数。概率 0 表示不会掉。
- **可由游戏发放。** 标在物品上。只表示这种途径存在，不把物品发给任何玩家。

一个技能最多对应一本技能书。技能从某关获得，就是这本技能书挂在那个 Boss 上。技能页只显示这些掉落，修改仍写在技能书那一条上。

击杀时每条掉落各自掷一次。两件物品可以同一次都掉，也可以都不掉。数量是这一次掷中之后掉几个。手机这一版还不进行击杀，这条规则先由服务器上的纯函数测试保住。

玩家进度只保存境界、物品、技能的稳定编号，也就是现有的 slug。名称和数值从当前已发布版本读取。学习条件里的境界指「达到该境界或更高」。

## 后台页面

制作后台沿用现有页面，并增加关卡。不出现运营后台的页面。

- **境界。** 编辑上面列出的境界字段。
- **关卡。** 编辑 Boss。从已有物品里添加掉落，填写概率和数量。
- **物品。** 编辑物品字段。勾选「可由游戏发放」。也可以把物品挂到某个 Boss 上。这里和关卡页改的是同一条掉落：同一个 Boss 加同一件物品只有一条，再次保存是在改概率和数量。
- **技能。** 编辑描述、角色、五项数值、所需境界和前置技能。不在技能上勾选发放，也不在这里新建掉落。
- **发布。** 沿用一次发布。发布的是整份草稿。

## 发布

发布成功后，草稿冻成一个新版本。正在玩的人下次读取时用这个版本。发布失败则线上仍是上一个版本，页面列出每一条原因。

发布前全部通过才生效：

- 每条掉落的 Boss 和物品都在这份草稿里。
- 概率、数量符合上面的范围。不合范围的掉落在保存时就拒绝，不会进草稿。
- 每本技能书指向一个存在的技能，且没有两本技能书指向同一个技能。技能可以暂时没有技能书。
- 前置技能都存在，并且不能形成环。
- 草稿里至少有一个境界，并连成一条链。没有被其他境界指向的境界只有一个，下一境界为空的境界只有一个。不能分叉，不能绕圈。
- 已经在任一已发布版本里出现过的境界、关卡、物品、技能编号，不能从新草稿里删掉。可以改名称和数值。

没有已发布内容时，修炼结算失败，和现在一样。玩家请求里自带的修为、掉落和技能等级，服务器不采用。

## 游戏端

服务器只认最近一次发布成功的版本。已经接上的修炼和突破，用这份里的境界计算。

关卡、掉落、物品和技能这一版做到能编辑、能发布、能被服务器读到。手机上的历练、行囊、功法仍不开放。以后接上时，掉落和能否学习由服务器按已发布内容计算后返回。

## 这一版不做

- 运营后台，以及把物品发给某个玩家。
- 合成、坊市、门派等其他获取途径。
- 五行、停留时间、通关或交物品才能突破。
- 关卡进入条件。
- 在手机上打 Boss 或学习技能。
