# 调研放置修仙市场

提出或扩大玩法前必须先跑完本流程。没有出处的句子不能写成「应该做」。

## 硬限制

- 不复制竞品代码、美术、文本、数值表、关卡名、道具名、受保护名称。
- 只记录**可观察的玩法结构**（循环、系统种类、节奏形状、回访理由）。
- 不把 SEO 软文、未标注的「白皮书」、攻略站二手发挥当成实测。
- 不因「像某款竞品」就直接开新系统。是否纳入当前一版，看 ADR-0006、`docs/product/mvp-scope.md` 和用户确认。

## 流程

1. 列出至少 **3 个**国内放置修仙/修真产品或公开方案，外加 **1 份**通用增量/放置设计资料。
2. 对每个对象用 WebSearch / WebFetch 打开**能核对的页面**（商店简介、官方论坛、玩家攻略、设计文）。记下 URL、日期、作者类型（官方 / 玩家 / 营销站）。
3. 每个对象只填能被原文支撑的系统，缺证据就写「未见」。至少覆盖：
   - 主循环（玩家重复做什么）
   - 成长梯子（境界/关卡/重置）
   - 离线怎么结算、有没有上限或衰减
   - 除「数字涨」以外的选择（功法、洞府、丹药、目标等）
   - 回访理由（日次数、墙、重置、事件）
4. 对照本仓库：`game/resources/config/idle_rules.json`、`docs/product/mvp-scope.md`、`docs/design/cultivation-foundation.md`。
5. 分成四栏，每条必须挂来源编号：
   - **可借鉴**：结构，不抄内容
   - **可优化**：竞品痛点或我们已落后的点
   - **可融合**：两家以上都有、且能落在现有「挂机→突破」上的
   - **先不做**：超出 ADR-0006 已确认的第一版，或只会变成另一套互不相干的循环
6. 把结果写入 `docs/research/`，文件名带日期。旧报告过期就新开一篇，不要改历史出处。
7. **禁止**在本技能里直接开干功能。设计走 `design-game-feature`，且必须引用这篇报告。

## 报告模板

```markdown
# 放置修仙市场对照 YYYY-MM-DD

## 方法
检索词、日期、收录/排除规则。

## 来源
| # | 对象 | URL | 类型 | 可信度 |
|---|------|-----|------|--------|

## 各对象结构
每对象：主循环 / 梯子 / 离线 / 选择 / 回访 / 未见。

## 跨产品重复出现的结构
每条后面写来源编号。

## 对照本项目
我们现在有什么、缺哪一类结构（只写事实）。

## 可借鉴 / 可优化 / 可融合 / 先不做
每条带来源。抄名称或数值的一律删。

## 证据不足
还要打开哪些页面或真机才能下结论。
```

## 完成标准

- 新报告已落盘，且每条建议都能指回来源。
- 没有「我觉得玩家会…」这类无出处句。
- 用户若只要结论，先给报告路径，再给四栏摘要。
