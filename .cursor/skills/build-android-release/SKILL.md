# 构建 Android 发布候选

本技能默认只在本地生成候选文件。上传、切换线上 manifest、发布和使用真实签名材料必须再次得到用户确认。

## 前置检查

- 工作区无意外改动，目标提交和版本号明确。
- Godot、Android SDK/Gradle、插件及 GUT 版本已锁定。
- 所有质量门禁通过，存档迁移和上一版本升级已验证。
- Release 使用固定签名身份；密钥仅通过本机安全路径或环境变量提供，不进入仓库和日志。

## 构建流程

1. 确定应用版本、内容版本、最低兼容应用版本和构建提交。
2. 执行完整无头验证与测试。
3. 构建 Release APK；需要内容更新时单独导出 PCK。
4. 为文件计算 SHA-256 和字节大小，生成版本化 manifest。
5. 校验 manifest 签名、下载 URL 结构、可用空间规则和回滚目标。
6. 在测试设备执行干净安装、同签名覆盖安装、旧存档升级、内容包激活与失败回滚。
7. 输出到 `builds/development/` 或经确认后的 `builds/release/`，不得自动上传。

## 必须停止的情况

- 签名身份变化、密钥缺失或可能泄漏。
- 版本号倒退、包名变化、存档迁移失败、哈希不一致。
- APK 安装权限/系统确认流程未验证。
- 当前内容包与应用版本不兼容或无法回滚。

## 输出

列出版本、提交、文件路径、大小、SHA-256、签名摘要、设备测试结果、回滚版本及“未上传/未发布”状态。
