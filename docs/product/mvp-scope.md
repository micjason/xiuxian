# 产品边界与长线路线

2026-10-02 起，产品边界以 [ADR-0006](../decisions/0006-online-product.md) 为准。下文若与它冲突，以 ADR-0006 执行。

已发布客户端是应用 `0.6.3`、versionCode 20、本地存档 schema 5。后台、接口和数据库尚未实现。

## 产品定位

- Android 优先的竖屏放置修仙游戏，目标是可上架、可给多人玩的完整版本。
- 组成是 Godot 客户端、后台管理、后端接口和 PostgreSQL。
- 修为、战力、突破和掉落由服务器计算后返回给客户端展示。
- 参考同类产品的交互密度，但不复制其名称、文本、数值、美术或代码。

## 可玩闭环

修为轴：

1. 玩家随时间获得修为。
2. 界面展示当前修为、获取速率和下一境界需求。
3. 修为满足条件后可尝试突破。
4. 突破成功进入下一境界，并提高修炼效率。
5. 退出并再次进入后，按统一规则结算离线收益。

战力轴（ADR-0003，与修为轴同时结算）：

1. 玩家选定已解锁关卡，挂机时按公式自动战斗。
2. 战斗记录与掉落进入行囊。
3. 按境界穿戴装备、学习功法，提高战斗数。
4. 战力与境界足够后可挑战下一关，掉落更高品质装备与更高阶技能书。

经营与传承（ADR-0005，分里程碑建设）：

1. 洞府经营把历练素材和经过时间转成丹药、定向装备与功法研修，反哺修为轴和战力轴。
2. 章节、见闻和建设成果在阶段终点形成可选传承。
3. 传承保留永久记录与有限路线选择，以局部重启改变下一轮路径；玩家可拒绝传承并继续当前轮。

完整页面、供需、解锁和失败防线见 `docs/design/long-term-progression.md`。

## 当前已具备（0.6.3 / schema 5 客户端）

- 可配置的境界、关卡、怪物、装备、功法与修炼/战斗数值。
- 可靠的本地存档、备份，以及迁移到 schema 5。
- 离线时间与一次结算（修为 + 历练）。
- 竖屏底栏：修炼、历练、洞府、行囊、功法。设置在顶部齿轮。
- Android 开发包的可重复构建。
- 为内容包和 APK 两层更新预留明确接口。

## 长线玩法仍按里程碑做

这些系统还没有全部做成线上版本。做的时候结算改到服务器，不再加进手机本地结算。

- 阶段目标、资源账本、确定性奖励与随机保底计数。
- 洞府中枢、灵田、丹房、器室、藏经阁；每个设施分里程碑发布，但发布时必须有完整投入、产出、选择和兜底。
- 多域共用一次 `TimeService` 离线结算，经营队列不能重复领取同一段时间。
- 持久临时收纳箱、设施产出缓存和传承恢复快照。
- Day 1 / 7 / 30 / 90 / 180 的压缩时间模拟与 schema 4→5 迁移验证。

## 第一版线上要做

- 玩家注册和登录。
- 打开游戏时由服务器结算修炼、突破和战力。
- 后台编辑境界、技能、物品的草稿，并发布给客户端。

## 明确不做

- 断签惩罚、真实时间过期的关键成长、限时绝版成长。
- 无限随机重铸、把未审核脚本放进内容包。
- 在服务器和接口尚未就绪时，把新的进度规则继续做进手机本地结算。
- 复制竞品名称、文本、数值、美术或代码。

排行、斗法、聊天、跨服和付费不在第一版。它们不再被产品边界禁止，做之前另写设计和 ADR。iOS 与商店上架是目标，当前发布渠道仍是 Android APK 热更。

## 产品变更门槛

任何新增系统先说明其对双轴、经营供需、传承、账号进度、已发布配置、测试和工期的影响。新增系统必须做到闭环，禁止先放空页面。改变 ADR-0006 的组成、权威数据或第一版范围时，必须由项目负责人确认并新增 ADR。
