## 后台
- **装备配置**：上面切换「装备 / 套装」；右上角 发放记录 / 补发装备 / 重新生成数值 / ＋新建装备（或 ＋新建套装）。列表多了「来源（公式 / 手动）」「套装」两列和筛选，手动装备排在前面。
- **新建装备抽屉**：图标（从 eq_* 图标里选）、名称、所属套装（显示“已有 n / 6 件”）、大境界、需求境界、部位（套装里已占的部位不能选）、品质、描述；属性手填，旁边显示同境界同部位同品质的公式值、实时战力和「比公式低 x%」。
  编号保存后自动生成 `gear_m_0001…`。「参与随机掉落」默认关（关着只能通过指定掉落、补发获得）；开了才用掉率倍数。可以强化、分解，规则和公式装备一样（按品质）。有玩家穿着时不能改部位。公式的 90 件保留。
- **套装**：基本信息、6 个部位的成员卡（只收手动装备，每个部位最多 1 件，同一大境界，一件只能属于一个套装）、套装加成档位（2–6 件，每档 1–4 条属性，百分比或固定值，各档叠加）。可以删除套装（成员会被移出）。
- **关卡「指定掉落」**：单独组件 `views/config/stages/StageDesignatedDrops.vue`，只挂在关卡抽屉里（`StagesView.vue` 只改了 7 行）。每条：装备、触发（普通怪每只 / 首领首通 / 首领重复）、概率 0.01–100%、数量 1–10，最多 20 条。和随机掉落同时生效，各自单独抽。没碰 BossEditor 和首领输入。
- **补发装备**（`components/GrantDrawer.vue`，按 equip_grant.png）：可以选多个玩家（最多 100 人）、多件装备（最多 10 行，每行 1–20 件）；原因从固定列表选（补偿 · 奖励未到账 / 补偿 · 服务器故障 / 活动奖励 / 测试 / 其他），备注必填；提交前预览并二次确认。
  一次补发有一个补发单号，全部成功或全部不发；重复提交不会多发。入口：装备配置页、玩家管理的行操作和详情。
- **发放记录**：操作日志 → 「装备发放」（`?tab=grants`），按来源、玩家、日期筛选，分页。
- **配置概览**新增三块：
  - 功法栏位：「到达某境界开放 N 个栏位」，可以加多档；
  - 新手设置：初始境界、新手物品（最多 20 行）；
  - 部位与品质：只读，服务端统一的表。
  强化规则里去掉了红色。
- **物品**：类型、品质、可叠加、图标（材料 / 丹药 / 功法书的图）都可以改。**功法**：品阶、所需境界、前置功法可以改（批次①修复后已经可编辑，这次复核过）。
- **去掉的字段和过时说明**：
  - 最低客户端版本号、挂机击杀上限（数据库列也删了）；
  - 「其他全局参数（只读）」区（只剩一句指向配置概览）；
  - 突破成功率的 6 个列；

## 套装加成
- 穿着的套装件数够了，那一档就生效。计算顺序：先把百分比乘到总属性上（境界 + 功法 + 装备），再加固定值。战力、战斗属性和战力明细（「套装」一行）都算进去了。
- `/me/state` 多返回 `activeSets`；`/content/current` 多返回 `gearSets`（名字、档位、成员）。
- 游戏装备详情新增套装块：
  - 套装名和「已有 x/n · 穿戴 y/n」；
  - 成员列表（✓ 穿着 / ○ 已有 / · 没有）；
  - 各档加成，已生效的显示为绿色。

## 功法栏位
- `globals.artSlotRules` = [{minRealmOrder, slots}]，按满足条件的最大一档开放。服务端只计算前 N 个运转中的功法，运转第 N+1 个会报错，并写明哪个境界开放下一栏。
- `/me/state` 多返回 `skillSlots {open, max, next}`。游戏功法页按这个画 N 个栏位，没开放的栏位显示「X 开放」。
- 默认值是从第一个境界起 3 个栏位，和以前一样，所以不会削弱现有玩家。
