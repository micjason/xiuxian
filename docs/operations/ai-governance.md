# AI 开发治理

## 权限模型

主 Agent 对一个功能从设计到验证负责，可在已确认范围内自主：

- 阅读、创建和修改项目文件。
- 安装已批准且锁定版本的项目依赖。
- 运行 Godot、测试、格式化、静态检查和本地构建。
- 创建小而完整的里程碑 Git 提交。

以下操作必须由用户明确确认：

- 扩大 MVP、改变核心玩法或引入付费成本。
- 破坏性存档迁移、删除原始素材或放弃用户改动。
- 新增外部服务、账号系统、遥测或收集用户数据。
- 使用/轮换真实签名材料和密钥。
- 上传、发布、切换线上 manifest、创建公开仓库或发送外部消息。
- 强制推送、改写共享历史和不可逆操作。

## 工作循环

1. 从当前需求提取可观察验收标准和非目标。
2. 检查产品边界；重大取舍写 ADR。
3. 小步实现，每一步运行最相关验证。
4. 完成后检查 diff、测试、文档、素材登记、密钥和生成物。
5. 创建里程碑提交，汇报提交、验证与剩余风险。

任何“完成”声明必须附实际证据。无法运行的检查标记为跳过并说明原因。

## Agent 分工

首期不维护多个常驻开发 Agent。一个主 Agent 保持端到端上下文，降低场景、数据和存档协议冲突。

只有满足以下条件才使用并行专用 Agent：

- 任务互相独立，例如资料研究、测试审查或安全审查。
- 文件所有权不重叠，或专用 Agent 只读。
- 主 Agent 最终统一检查结论和集成结果。

同一功能的场景、脚本、数据和测试不得交给多个 Agent 无协调并发修改。

## 插件治理

插件不是默认答案。引入前记录用途、版本、许可证、维护状态、Godot 4.7.2 兼容性、替代方案和移除成本。

首个候选仅为 GUT 9.7.x，用于 GDScript 单元及必要场景测试。插件代码固定版本进入 `game/addons/`，升级单独提交并运行完整测试。未经 ADR 不引入架构框架、可视化脚本框架或不必要的 Agent 插件。

## 失败与暂停

遇到密钥风险、无法解释的数据丢失、范围冲突或重复失败时立即停止变更，保留证据并请求决策。普通测试失败、临时网络问题和可恢复工具问题由 Agent 自主诊断，不把技术摩擦转嫁给用户。
