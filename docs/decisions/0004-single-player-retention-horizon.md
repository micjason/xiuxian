# ADR-0004：单机长线留存周期

- 状态：部分被 ADR-0006 取代。离线单机、禁止账号和禁止服务器的条款不再执行。3–6 个月的内容层次和「Day N 不是日历活动」仍然有效。正文保留 2026-09-11 的原文，执行时跳过已被取代的条款。
- 日期：2026-09-11
- 决策者：项目负责人

## 背景

`0.1.15`、存档 schema 4 已经完成约五小时的修为与历练双轴目录，但“把当前系统试一遍”和“愿意持续玩 3–6 个月”是两种产品目标。继续只向境界表、关卡表追加更大的数字，会让中后期只剩等待；依赖每日签到、限时活动、排行或服务器又会破坏单机离线优先的边界。

项目负责人已确认：首发形态继续是 Android 竖屏、单机离线优先；目标留存周期改为 3–6 个月；允许重新评估 ADR-0003 之后的产品边界；所有系统需要形成深入闭环，但按里程碑交付。

## 决策

### 产品时间尺度

- 以 Day 1 / 7 / 30 / 90 / 180 作为内容与系统解锁检查点，而不是要求玩家连续登录的日历活动。
- “Day N”表示典型玩家累计推进到该阶段的目标窗口；断签、晚回或长期离线不会永久错过内容，也不会损失连续奖励。
- 五小时目录继续承担新手验证和第一段可玩闭环，不再代表完整产品上限。
- 3–6 个月来自新选择、生产计划、构筑变化和可控传承，不来自把同一等待时间无限放大。

### 离线与网络边界

- 所有核心成长、经营、战斗、传承、存档导入导出均可在无网络时完成。
- 网络只可用于玩家主动触发的版本检查和内容包下载；失败时不得阻塞进入已有本地内容。
- 不做 PvP、排行榜、聊天、公会多人玩法、服务器裁决进度或强制联网。
- 不用限时活动、签到断档、体力过期、离线生产被清空等方式制造回访压力。

### 留存结构

采用“长线双轴 + 经营供给 + 传承复玩”的结构：

1. 修为轴决定境界、修炼效率和内容资格。
2. 历练轴决定关卡推进、战斗构筑和稀缺素材来源。
3. 洞府经营把时间和素材转成可计划的定向产出，缓解纯随机掉落。
4. 传承在完整阶段结束后提供自愿的局部重启与永久选择，改变下一轮路径，而不是清空一切。

系统边界、页面信息架构与里程碑由 ADR-0005 和 `docs/design/long-term-progression.md` 具体规定。

### 版本与存档基线

- 当前事实基线固定为应用 `0.1.15`、存档 schema 4。
- 下一阶段的计划目标是 schema 5，用于承载长线目标、经营队列、资源账本、保底计数与传承状态。
- schema 5 只表示存档能力边界，不表示所有 Day 180 内容必须一次发布；未解锁系统必须有稳定默认值并可跨内容版本读取。

## 备选方案

- 只追加境界和关卡数值：未采用。内容便宜，但不能提供新的决策，也会让中后期只剩线性等待。
- 依靠每日任务、签到和限时活动：未采用。会惩罚离线玩家，并把 3–6 个月目标误做成日历束缚。
- 依靠 PvP、排行和公会竞争：未采用。需要服务器与持续运营，和单机离线优先冲突。
- 一次上线全部长线系统：未采用。风险集中，无法逐段验证供需、节奏、迁移和失败防线。

## 后果

### 正面

- 玩家可以按自己的节奏离开和回来，不因错过日期失去关键成长。
- 五小时双轴成果被保留为长线入口，而不是推倒重做。
- 经营提供定向目标，传承提供阶段收束，能支撑数月而不依赖竞争和运营活动。

### 代价与风险

- 配置、存档和离线结算从两个产出域扩展到多队列，迁移与幂等测试成本显著增加。
- 若经营只是定时收菜，或传承只提供百分比加成，仍无法形成长线选择。
- 3–6 个月是设计目标，不是未经测试的承诺；必须通过里程碑数据和人工长时模拟复核。

## 验证与回滚

- 每个里程碑必须至少具备来源、消耗、选择、反馈、失败兜底、存档迁移和自动验证，禁止发布空页面。
- 用压缩时间模拟 Day 1 / 7 / 30 / 90 / 180，验证没有资源死锁、单一最优解和不可恢复重置。
- 任意阶段断网、杀进程或跨版本加载，都能继续已有本地进度且不重复结算。
- 若某一经营或传承模块不成立，回滚该模块的入口与配置；保留 schema 5 中可忽略的默认字段，不把存档降级写回 schema 4。
