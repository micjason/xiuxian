# 后台进度模拟（最勤奋玩家）设计

日期：2026-10-30  
状态：**已拍板**（成鹏确认方案与分段设计）  
读者：负责人 / 成鹏 / 开发  
前置：开发期配置「保存即生效」（无草稿双轨）；模拟读当前生效配置

---

## 1. 目标

后台单独一页「进度模拟」：用**最勤奋玩家**假设，把当前生效的境界 / 关卡 / Boss / 装备 / 强化 / 技能 / 洞府配置快进推一遍，几秒出结果。用来发现卡死点（例如 Boss 战力门槛玩家永远够不到），方便改数。

不做：导出 CSV、草稿配置、付费/活动/社交。

---

## 2. 玩家假设（最勤奋）

- **日节律**：游戏日内在线 16h + 挂机 8h（固定，本版不可改）。
- **行为**：能打的 Boss 必打；能强化的装备强化到当前材料/等级上限；洞府灵仆按最优分配；该突破就突破；技能按配置自动装配（战斗始终全自动，无手动大招）。
- **策略**：一律最优，不做手动选装 / 偏科流派。
- **目标**：默认推到 **大乘**；页顶可改目标境界后再跑。
- **卡死**：对「下一个 Boss」连续刷满 **10 游戏天**仍打不过 → 标红停跑。

---

## 3. 触发与入口

- 后台导航新增单独页：**进度模拟**。
- 页顶：目标境界（默认大乘）+「跑一遍」按钮。
- 点跑 → 服务端同步/短时任务推演 → 几秒返回结果（模拟时钟大幅加速，非真实天数等待）。
- 读**当前生效配置**（保存即生效后的 live 表）；不读任何草稿。

---

## 4. 推演核心循环

服务端按游戏时间推进（内部可按「事件」跳，不必逐秒）：

1. 在线段：优先尝试挑战当前下一 Boss / 关卡；成功则结算掉落、穿戴更优装、强化、突破；失败则记入「对该 Boss 的刷天」。
2. 挂机段：挂当前最高可稳定刷的关，结算材料 / 装备 / 修为等。
3. 洞府：按日或按事件结算灵石 / 灵木 / 灵仆产出，并用于升级与强化。
4. 战力重算：穿戴 / 强化 / 境界 / 技能变化后立即重算，供下一场战斗判定。
5. 终止条件（任一）：
   - 到达目标境界（含大乘默认）；
   - 对下一 Boss 连续 10 游戏天打不过（卡死）。

战斗判定复用现有服务端战斗/战力门槛逻辑（或与其等价的只读判定），避免前端公式假绿灯。

---

## 5. 结果页（三块）

### 5.1 上：时间轴总览

表格列建议：游戏天 | 境界 | 关卡/Boss | 战力 | 装备档 | 技能档 | 状态  

- 正常行：推进节点摘要（按天或按重大事件聚合一行均可，以可读为准）。
- **卡死行整行标红**。

### 5.2 中：卡死明细（若停于卡死）

- 卡在哪一 Boss / 关卡门槛  
- 差多少战力（或其它门槛字段）  
- **红灯维度**：战力 / 装备强化 / 技能 / 关卡门槛（可多亮）  
- 建议优先改哪类配置（文案级提示，不自动改数）

### 5.3 下：真人流水账明细

按游戏时间顺序的事件流，像真人玩一样可读，例如：

- 第 1 天 0h：开局境界 / 战力  
- 第 1 天 2h：打过 Boss X，获得装备 Y，穿戴后战力 Z  
- 第 1 天 3h：挂机关卡 A  
- 第 1 天 11h：获得材料/装备…，强化/穿戴后战力…  
- …

默认折叠；**卡死日附近默认展开**。本版仅页面查看，不提供导出。

---

## 6. 范围

| 覆盖 | 本版不做 |
|------|----------|
| 境界突破 | 社交 / 交易 |
| 关卡 / Boss | 付费 / 内购 |
| 装备掉落与穿戴 | 限时活动 |
| 强化到当前可强化上限 | 手动选装策略 |
| 技能按配置自动装配 | 导出表格 |
| 洞府灵仆最优分配与产资源 | 草稿配置模拟 |

---

## 7. 验收

1. 改一条 Boss 战力门槛后保存 → 点「跑一遍」→ 几秒出表，卡死点与改前不同。  
2. 默认目标大乘；改成更低境界能提前正常结束。  
3. 人为造「永远打不过」的 Boss → 满 10 游戏天标红停，且流水账能看到刷天过程。  
4. 流水账含：境界变化、Boss 胜负、掉落、穿戴、挂机关、材料、强化后战力。  
5. 总览在上、卡死明细、流水账可展开；无导出按钮。

---

## 8. 实现备注（给开发）

- API 建议：`POST /admin/sim/progression`（body: `{ targetRealmId? }`）→ 返回 `{ overview[], stuck?, timeline[] }`。  
- 可参考仓库已有 `tools/sim` 离线思路，但**必须以 live 生效配置 + 服务端判定为准**，不要只扫静态 JSON。  
- 耗时目标：点一次几秒内返回（内部事件跳进）；若超限返回部分结果 + 超时说明。  
- 后台路由：独立页，不嵌配置概览（成鹏选 A）。
