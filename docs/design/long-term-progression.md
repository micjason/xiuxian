# 长线成长与留存总设计

本文把 ADR-0004 的 3–6 个月目标和 ADR-0005 的“长线双轴 + 经营供给 + 传承复玩”落实为可分段验收的产品设计。它扩展而不替代 `docs/design/five-hour-loop.md`、`docs/design/five-hour-skills.md`、`docs/design/cultivation-foundation.md` 与 `docs/design/adventure-loop.md`。

事实基线：

- 当前应用版本：`0.1.15`。
- 当前存档：schema 4。
- 下一阶段计划目标：schema 5。
- 平台与形态：Android 优先、竖屏、单机离线优先。
- 目标周期：典型玩家用 3–6 个月走过首次完整传承和第二轮差异化成长。

“Day 1 / 7 / 30 / 90 / 180”是累计进度的设计检查点，不是必须在对应自然日登录的限时活动。玩家晚到、断签或长期离开，都能按自己的进度顺序解锁。

## 设计目标与硬边界

### 目标

1. 五小时后仍有新的选择，而不只是更大的境界消耗和敌人血量。
2. 修为与历练继续互锁，经营负责定向供给，传承负责阶段收束和复玩差异。
3. 每次回来能在 1 分钟内看懂“离线发生了什么、现在缺什么、下一步做什么”。
4. 15–30 分钟整理会话有装备、功法、设施和目标之间的真实取舍；纯挂机玩家也不会永久卡死。
5. 所有关键成长离线可用、可迁移、可恢复，不依赖运营日历或服务器裁决。

### 硬边界

- 不做 PvP、排行榜、聊天、公会多人玩法、跨服、强制联网。
- 不复制竞品代码、美术、文本、数值表、专有名称或具体活动结构。
- 不做真实时间过期的关键资源、断签惩罚、限时绝版成长、体力清零。
- 不做付费加速、广告换关键资源、服务器真挂机。
- 不靠无限随机重铸、多套一键装配或无上限乘区堆叠制造时长。
- 网络仅用于玩家主动触发的版本检查与内容包下载；网络失败不阻塞本地游戏。

## 总循环

```text
经过时间
  ├─> 修炼：修为 ─> 突破 ─> 境界资格与效率
  ├─> 历练：击杀 ─> 装备/残页/药材/矿材/兽材/灵石
  └─> 洞府：灵田/丹房/器室/藏经阁队列完成

境界资格 + 战斗构筑 ─> 新地点/头目/配方/设施层级
经营定向产出 ─> 缓解修炼与历练短板
章节、图鉴、建设成果 ─> 可选传承
传承路线 ─> 改变下一轮起点与解题方法
```

四层都必须互相服务：

- 修为轴给历练和设施提供资格，不直接买齐一切。
- 历练轴提供经营投入，并用经营产出解决具体短板。
- 洞府把随机战利品变成可计划目标，不独立追求一套“经营战力”。
- 传承奖励完成过的选择，不替玩家跳过当前内容。

## 页面信息架构

### 导航演进

`0.1.15` 当前底栏保持“修炼 / 历练 / 行囊 / 功法 / 设置”。在洞府中枢、灵田、丹房都达到可发布深度后，一次性迁移为：

```text
修炼 / 历练 / 洞府 / 行囊 / 功法
```

- 原“功法”保留一级入口，并增加门派、传承配方和构筑联动。
- 原“设置”移入全局顶栏齿轮，版本更新与存档导入导出仍可到达。
- 不增加第六底栏，不在设施未完成时提前展示空洞府页。
- 页面迁移不改变领域 ID，不以 UI 节点路径作为存档字段。

### 全局返回态

每个一级页顶部统一显示：

- 当前境界与修为进度。
- 当前战力和正在历练的地点。
- 洞府正在运行的队列数。
- 离线容纳剩余提示，仅在接近上限时出现。

底栏红点只表达可立即处理的状态：可突破、队列完成、行囊溢出、目标可领取。不能用红点表达“去看看”或制造永久未读。

启动后的离线摘要按以下顺序展示：

1. 有效离线时长和被上限截断的时长。
2. 修为、击杀、关键掉落和经营完成。
3. 行囊/临时收纳箱状态。
4. 最多三条下一步建议，分别指向可突破、可过墙或可启动队列。

### 修炼页

首屏只放当前决策，不塞满所有长期系统：

- 境界卡：当前境界、修为、效率、下一阶消耗、突破按钮。
- 效率来源：境界、运转心法、丹药、传承印记分别列出，不隐藏乘区。
- 当前功法：1 个心法栏和已解锁战技栏，可直接换下。
- 下一目标：距离新地点、设施层级或传承条件最近的一项。

二级页：

- **境界**：当前和下一境界、历史突破、规则说明。
- **功法**：沿用 `five-hour-skills.md` 的分类、运转、卸下、小成与短板预览；后续加入藏经阁研修来源。
- **传承**：未开放时只显示可解释的条件预览；开放后显示保留/重置清单、路线效果和恢复快照。

### 历练页

首屏延续当前文字战斗，不要求视觉战斗：

- 当前地点、层级、敌人、击杀效率和战报摘要。
- 攻/防/速/功法短板，明确“差多少”和可解决入口。
- 地图按章节折叠，只展示当前章节、上一章和下一目标，避免 Day 1 看到 Day 180 长列表。
- 掉落预览区分确定性累计奖励、随机掉落和累计保底进度。

二级页：

- **地图**：地点外围/深处/头目及解锁条件。
- **驻留**：当前挂机目标、收益权重和最近战报。
- **远行**：Day 30 后开放一个非并行战斗队列，派出后角色仍可修炼与经营，但同一角色不能同时在两个地点领取完整战斗收益。
- **见闻**：怪物、头目、已见装备和功法，不提供排行或联网比较。

### 洞府页

洞府首屏是供需看板，不是房间装饰页：

- 中枢等级、离线容纳、并行队列数。
- 当前四设施状态：空闲、生产中、完成、缺料。
- 三条资源缺口：当前主线短板所需材料、来源和预计路径。
- 队列完成后先进入安全产出缓存，再由玩家收取或自动入账；唯一物品不能因满包丢失。

设施二级页：

- **灵田**：选种、投入、产量、耗时、收获用途；种子基础种可循环保留，避免种完后断种。
- **丹房**：配方、药材、灵石、耗时、成品效果；只能制作已发现配方。
- **器室**：合阶、拆解、定向胚子、温养；每次结果在开始前可预览，不做无限随机词条重铸。
- **藏经阁**：已见功法的研修、小成补足、构筑知识；不能跨境界凭空造高阶书。
- **中枢**：升级条件、队列容量和离线容纳；不直接提供全战斗数乘区。

### 行囊页

- 顶部继续使用五槽装备板，并显示换装后的主短板变化。
- 分类为全部 / 装备 / 丹药 / 材料 / 功法；配方作为知识解锁，不占物品格。
- 重复装备详情同时给出穿戴、合阶、拆解三个有条件动作。
- 材料详情写明“主要来源”和“可用于”，允许一键跳到已解锁设施。
- 满包时普通物品按玩家策略处理；唯一物品、首见物品和目标奖励进入持久临时收纳箱，绝不静默丢弃。

### 功法页

- **运转与参悟**：保留功法分类、运转栏、小成和短板预览。
- **门派**：查看职位、贡献、NPC 同门与定向传承配方。
- **构筑说明**：展示功法与灵兽、丹器、洞府的联动效果。
- 设置、存档导出与版本更新统一由顶栏齿轮打开，并提供明确返回。

## 系统供需

### 资源角色

| 资源/状态 | 稳定来源 | 随机或加速来源 | 主要消耗 | 防死锁规则 |
| --- | --- | --- | --- | --- |
| 修为 | 时间、境界效率、心法 | 回气丹 | 突破 | 时间永远可产；突破无随机失败 |
| 灵石 | 章节目标、头目首胜、历练累计 | 普通战斗掉落 | 中枢升级、设施配方 | 主线目标给最低建设量 |
| 药材 | 灵田 | 历练、头目 | 丹房 | 基础种可循环，不会全部耗尽 |
| 矿材 | 地点累计奖励 | 怪物掉落、装备拆解 | 器室、中枢 | 地点累计条提供确定性最低量 |
| 兽材 | 指定地点累计奖励 | 怪物掉落 | 器室、设施升级 | 已解锁地点可回刷，不设次数 |
| 装备 | 地点保底、器室定向胚子 | 战斗掉落 | 穿戴、合阶、拆解 | 槽位胚子有累计保底 |
| 功法残页 | 头目累计、章节目标 | 对应地点掉落 | 入门、小成、藏经阁研修 | 只对已见功法开放定向研修 |
| 丹药 | 丹房 | 战斗掉落 | 限时修炼/战斗增益 | 不是任何永久解锁的唯一条件 |
| 见闻 | 首见、击杀、首胜 | 无 | 解锁配方、传承条件 | 进度永久保留，不会倒退 |
| 传承点 | 完成章节与首次传承 | 高完成度追加少量 | 有上限的传承印记 | 不可购买，不可无限刷同一里程碑 |

### 供需闭环

#### 修为与丹药

- 时间和心法给稳定修为；回气丹只改变一段效率，不替代基础产出。
- 修为只用于突破，避免玩家在“开设施还是升境界”之间踩不可逆死锁。
- 境界开放地点、配方和设施上限，但不会自动给战斗胜利。

#### 历练与器室

- 历练随机掉装备，同时按击杀累计条给指定槽位胚子或关键素材。
- 重复装备在“立即合阶”和“拆成定向材料”之间形成选择。
- 器室提供可预览的确定结果，让长期未掉某槽位的玩家仍能推进；随机红装仍保留惊喜，但不是唯一道路。

#### 功法与藏经阁

- 第一本残页用于入门，后续残页用于小成或研修。
- 藏经阁只作用于玩家已经见过且满足境界的功法，避免经营跳过历练发现。
- 战技栏有限，功法越多提供的是构筑宽度，不是全部被动相加。

#### 灵田与丹房

- 历练先提供基础种与少量药材，灵田建立稳定循环，丹房再将其变为短时工具。
- 丹药解决“这次突破要更快”或“这个头目缺防”的局部问题，不成为全天候必开税。
- 基础种收获时至少返还一次播种所需种量；高阶种可消耗但有累计兑换。

#### 洞府与双轴

- 中枢升级需要境界、章节与多来源素材，防止只挂机修为或只刷战斗就毕业。
- 设施产出必须指向当前可见目标：过墙、突破、定向装备或功法构筑。
- 经营不产独立“洞府战力”，也不单独开一套关卡。

#### 传承与当轮进度

- 当轮章节、见闻和设施建设产生传承资格与有限传承点。
- 传承印记分别偏向修炼、历练或经营起步，采用互斥或槽位上限。
- 第二轮仍要做核心循环，但路线、先后顺序和可用构筑发生变化；不能用永久倍率直接跳过整章。

### 数值与容量原则

- 同一层级的新来源应缩短等待或提供选择，不让总产出每加一个系统就无条件翻倍。
- 关键建设目标优先用累计量和确定性首胜奖励定标，随机掉落按加速项处理。
- 同时新增的资源家族每个里程碑最多两类；旧资源有稳定用途后再引入新资源。
- 队列并行数从 1 起，长期上限保持小而可读；扩容代表可计划性，不代表必须频繁上线。
- 当前 `0.1.15` 离线有效时长上限为 8 小时。里程碑 1 应把普通收益基础容纳调整到至少 24 小时，后续中枢可提高到 36/48/72 小时；所有系统共享同一有效时长。
- 到达离线上限后只停止新增普通产出，不扣库存、不让设施成品消失、不让敌人反向造成损失。

## 解锁路线

以下窗口按正常探索、偶尔离线和不查攻略估算。不得用自然日判断硬锁；若玩家提前达到前置条件，可以提前解锁，若晚到则按顺序补上。

### Day 1：双轴立住

玩家目标：

- 完成当前五小时目录的前段：理解修炼、突破、装备、功法运转、短板与离线摘要。
- 见到洞府预告，但在设施未完成前不出现可点空页面。

系统解锁：

- 修为与历练双轴、行囊、功法、设置保持 `0.1.15` 完整能力。
- 阶段目标只给主目标和少量教学支线。
- 第一次出现药材、矿材时明确其未来用途，但未开放设施前不大量掉落。

验收：

- 玩家不查攻略能解释修为和战力为什么是两条轴。
- 首次失败明确写出缺境界、攻、防、速或功法中的哪一项。
- 当天结束时没有必须联网、必须签到或会过期的资源。

### Day 7：经营形成最小闭环

前置：完成五小时目录、达到对应境界和首章头目累计目标，不检查自然日。

系统解锁：

- schema 5 迁移。
- 洞府中枢、灵田和丹房以完整闭环开放。
- 五底栏迁移到“修炼 / 历练 / 洞府 / 行囊 / 功法”，设置进入顶栏。
- 基础 24 小时普通收益容纳；离线摘要展示三域结果。
- 阶段目标、供需提示和安全产出缓存。

核心选择：

- 灵田种修炼向药材还是战斗向药材。
- 药材直接留给中枢前置，还是炼成一次过墙丹药。
- 心法效率与战技短板继续竞争有限功法栏。

验收：

- 灵田投入能追溯来源，丹药能在修炼或战斗中找到具体用途。
- 不收菜超过 24 小时不会丢失已完成成品，只损失上限之外的新增普通产出。
- schema 4 旧档迁移后装备、功法、境界和设置完全保留。

### Day 30：定向构筑成熟

前置：完成第二章节和洞府中枢阶段目标。

系统解锁：

- 器室：拆解、定向槽位胚子、现有合阶和温养。
- 藏经阁：已见功法的定向研修。
- 历练远行与第二批地点，但同一角色不重复领取两份完整战斗收益。
- 装备槽位保底、残页累计保底、图鉴与纪事。
- 中枢提供 36/48 小时容纳与第二个经营队列选择。

核心选择：

- 重复装备用于当前合阶，还是拆解追目标槽位。
- 残页用于现有功法小成，还是投入藏经阁补另一构筑。
- 经营队列投向突破效率、头目短板或长期中枢升级。

验收：

- 连续随机不利时，玩家仍能看见确定性目标和最多一个阶段内的完成路径。
- 至少两种构筑能通过同一章节，没有唯一必选设施顺序。
- 图鉴只记录已见内容，不提前泄露全部 Day 180 列表。

### Day 90：首次阶段收束

前置：完成首个长章节终点、达到规定境界、洞府和见闻条件。

系统解锁：

- 洞府专精：修炼、历练、经营三选一的当轮侧重，允许后续用游戏内普通资源重选但有冷却阶段，不收真钱。
- 传承预览、保留/重置逐项清单、效果模拟。
- 首次传承和独立恢复快照。
- 传承印记槽，首批路线保持少而互斥。

核心选择：

- 继续当前轮补图鉴和设施，还是按当前完成度传承。
- 选择偏修炼起步、偏历练掉落定向或偏经营队列的传承印记。
- 传承后先恢复哪条轴，路线应因印记而变化。

验收：

- 不传承也能继续游玩，不出现资源衰减或强制弹窗。
- 确认页能准确预览操作后的关键状态；中断后要么保持原轮，要么完整进入新轮，不能半重置。
- 恢复快照可独立加载，并且不会覆盖后续正常备份。

### Day 180：第二轮差异与长尾

前置：完成至少一次传承并走完第二轮差异化章节目标。

系统解锁：

- 第二批互斥传承印记和有限组合槽。
- 根据首轮路线改变的章节修饰、经营订单与构筑目标；不复制整套平行内容。
- 完整传承纪事、轮次对比和终局后持续沙盒。
- 中枢最高计划容纳 72 小时；继续保持单机离线结算。

核心选择：

- 用有限印记槽形成不同开局，而不是把所有永久加成都点满。
- 追求不同构筑、图鉴或经营效率，不以排行定义终局。
- 达到已发布内容末端后可以继续积累和整理，不自动清档、不强迫再次传承。

验收：

- 第二轮前 30% 的目标顺序和可行解法与第一轮有可感知差异。
- 不同路线在压缩时间模拟中都能完成，没有单一路线数量级领先。
- Day 180 之后无新内容时，游戏明确显示当前内容边界，不伪造无限任务。

## 失败防线

### 战斗与成长失败

- 战斗失败不扣修为、不损坏装备、不消耗关键入场资源；继续停留在已通过地点。
- 突破保持确定成功：修为不足不可点，满足条件即成功，不增加随机失败率。
- 短板提示必须给具体差值和至少一个已解锁解决方向。
- 头目随机掉落不是主线唯一门票；首胜、累计击杀或器室提供确定性替代。

### 随机与资源失败

- 关键槽位和功法使用累计保底，保底计数进入存档且内容更新不能静默清零。
- 每个强制投入都有稳定来源；基础种、基础配方和已解锁地点不会被一次消耗永久断掉。
- 配方开始前显示投入、产出和时长；结果在开始时确定，重启不能刷新结果。
- 取消未开始的队列全额退还；已开始队列按明确规则退还未消耗部分，唯一材料不得吞没。

### 容量与离线失败

- 行囊满时普通掉落按玩家设置处理；唯一、首见、保底和目标奖励进入持久临时收纳箱。
- 临时收纳箱不按真实时间过期。达到安全上限时暂停继续生成受保护物品并明确提示，不覆盖旧物。
- 经营成品先进入设施缓存；满包不销毁成品。
- 超过离线上限只截断新增收益，已有库存、队列投入和已完成成品保持不变。
- 时钟回拨按零时长处理，不倒扣、不让队列逆转，也不补发重复收益。

### 操作与传承失败

- 高价值拆解、传承和存档导入需要二次确认；确认页展示具体变化，不只写“是否确定”。
- 锁定、正在穿戴、传承标记和唯一物品默认禁止批量拆解。
- 传承前生成只读恢复快照；写入失败则保留原轮，禁止半完成。
- 玩家可以放弃预览并继续当前轮；不因拒绝传承失去内容。

### 迁移与内容版本失败

- schema 4 必须通过 `v4 → v5` 单向迁移，迁移前保留原文件，成功校验后才替换。
- 无法理解更高 schema 时拒绝写回；内容缺少旧 ID 时使用显式映射或安全占位，不能删除对应玩家资产。
- 内容包激活失败回滚上一份可用内容；核心本地循环继续可玩。
- 所有结算先生成内存结果，校验后原子提交；崩溃重启不得重复领取同一时间段。

### 节奏与认知失败

- 不使用每日任务列表、断签奖励和真实时间限时门票。
- 同屏主行动不超过三个；未解锁系统不给红点。
- 同一里程碑最多引入两个新资源家族，且首次获得时立即说明来源和用途。
- 连续两个阶段目标没有进展时，提供确定性追赶目标；不直接免费跳关，也不推付费入口。
- 内容末端明确标记“当前版本终点”，允许继续沙盒，不用假倒计时或虚假更新诱导等待。

## schema 5 计划

schema 5 在 schema 4 的修为、装备、功法运转、地点和设置之外，计划增加：

```text
payload
  progression
    milestone_id
    chapter_states
    deterministic_reward_counters
    pity_counters

  resources
    spirit_stones
    herbs_by_id
    ores_by_id
    beast_materials_by_id
    seeds_by_id

  homestead
    hub_level
    facility_levels
    active_queues
    completed_output_cache
    offline_capacity_seconds

  codex
    seen_ids
    first_clear_ids
    chronicle_entries

  inheritance
    cycle_index
    inheritance_points
    selected_marks
    unlocked_marks
    recovery_snapshot_metadata

  overflow
    protected_items
```

约束：

- 配方定义、设施数值、章节表和传承效果属于内容配置，不复制进存档。
- 队列存开始时间、结束时间、已预留投入和确定结果种子；不逐秒保存进度。
- 保底计数、受保护溢出和传承点不可由当前配置可靠重算，必须存档。
- schema 5 先提供稳定默认值，再分内容里程碑开放入口；未开放字段不得影响 `0.1.15` 既有状态。
- 迁移链保持相邻版本：`v1 → v2 → v3 → v4 → v5`。不从 v1 直接猜测 v5。

详细原子写入、统一时间和迁移规则见 `docs/architecture/save-and-time.md`。

## 分里程碑发布门槛

一个系统只有同时满足以下条件，才能从隐藏状态变为玩家可见：

1. 至少一个稳定投入来源和一个明确产出用途。
2. 至少一个玩家选择，而非只有领取按钮。
3. 完整的开始、进行、完成、取消和容量反馈。
4. 对随机不利、资源不足、满包、离线上限和中断有兜底。
5. schema 迁移、坏档恢复、重复结算和配置缺失有验证。
6. Android 竖屏下单手可达，返回路径不丢当前选择。
7. 文案与内容为本项目原创，不复制竞品表达和数值。

未满足任一项时，保留在开发配置中，不放“敬请期待”空页。

## 总体验收

- Day 1 / 7 / 30 / 90 / 180 压缩时间模拟均能从 schema 4 迁移后的真实状态起跑。
- 每个阶段至少有两条可行推进策略，且没有依赖联网、排行或真实日期的条件。
- 每类关键资源能从用途追溯到来源，也能从来源追溯到至少一个有效消耗。
- 关闭应用、断网、超过离线上限、时钟回拨、存档中断和内容包回滚都不会造成不可解释的资产损失。
- 首次传承前后都有可核对清单和恢复快照；拒绝传承仍可继续当前轮。
- 当前五小时目录的装备、功法、短板、套装、丹药、温养和见闻能力在长线页面迁移后仍然可达。
