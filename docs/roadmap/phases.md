# 开发分期：A 阶段（单人可玩）与 B 阶段（运营）

决定日期：2026-10-15。这篇是对 `03-dev-plan.md` 里「P7 上线准备」「P6 GM 工具」的补充：**在 A 阶段完成之前，不做任何运营和安全类功能。**

## A 阶段：核心玩法 + 后台，只有一个用户（项目负责人自己）

目标：一个人能把整条玩法链路玩通、后台能把所有玩法数据配出来。

范围：

- 修炼、突破、历练关卡、首领与掉落、文字战报。
- 装备六个核心部位（武器、头部、身体、手部、腿/鞋、饰品），法宝、灵宠的格子预留、第三期开放。
- 行囊：网格背包，初始容量 20 格，容量字段和界面保留；扩容道具以后由活动或任务发放，**没有购买入口**。
- 强化：分解装备得到强化经验（经验池没有上限，已穿戴的装备不能分解），经验给任意装备升强化等级；红色（仙品）也可强化；每个品质可配置突破节点（每 5 级等需要材料）。规则见 `docs/design/enhance_rules_proposal.md`（v2，客户已确认）。
- **没有货币，没有出售。**
- 后台：境界、物品装备、技能、关卡与首领、战斗公式、装备强化、发布中心、客户端安装包、公告与弹窗、操作日志、单一管理员。
- 游戏端界面：修仙风格的占位美术，结构按真实美术的尺寸做，换图不改布局（见 `docs/ui/ui_design_spec.md`）。

A 阶段明确不做：

| 不做 | 说明 |
|---|---|
| 版本回滚 | 去掉页面、对话框、菜单；后端本来就没有回滚接口，不新增 |
| 封号 / 解封 | 去掉界面提示；后端没有接口，不新增 |
| 补发物品 / 补偿 | 去掉界面提示；后端没有接口，不新增 |
| 邮件、礼包、兑换码、商品与订单 | 页面、路由、演示数据全部删除；侧栏底部只留灰色的「后续阶段」文字提示 |
| 物品锁定 | 客户端界面与本地记录都去掉 |
| 真实支付 | 不接 |
| 多管理员与权限 | 只有一个管理员角色 |

A 阶段保留：操作日志（成本低，调试用）、「清空进度」（单人调试要用）。

A 阶段完成的判定：从注册到打完当前最高关卡、分解、强化、换装、学功法，整条链路在真机上不靠改库就能走通；后台能配出这条链路的全部数字并发布。

## B 阶段：安全与运营（A 阶段完成后才开始）

按优先级：

1. 安全：HTTPS、限流与风控、存档校验、账号找回。
2. 版本回滚（含「游戏读取已发布快照而不是草稿」的前置确认）。
3. 封号 / 解封，补发与补偿（需要审计与幂等）。
4. 邮件、礼包、兑换码。
5. 商品与订单（真实支付另行决定）。
6. 多管理员与权限、数据看板、监控备份。

B 阶段开始前需要再确认：用户规模、发布平台（先 Android）、合规要求（目前决定先不考虑）。

- 后台：已删除回滚、封禁、补发、邮件、礼包、兑换码、商品订单；新增「装备强化」页（含按品质的突破节点表和曲线预览）；版本历史保留为只读对比。
